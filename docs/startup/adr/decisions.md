# 架构决策记录（ADR）

状态说明：“建议采纳”表示启动基线，尚非团队正式批准。每个决策实施后补 owner、日期、测试证据与变更记录。

## ADR-001 · Electron + React + 独立 Node sidecar
建议采纳。理由：共享 TypeScript 产品协议，Pi SDK 放独立 Worker；代价是包体、原生模块和打包复杂度。备选 Tauri 不进入首版双轨维护。验证：双平台签名包、IPC 安全与 Worker 崩溃不拖垮 UI。

## ADR-002 · Pi SDK 是执行依赖，不是产品框架
建议采纳。SDK 只在 pi-adapter 包出现；所有事件映射为自有协议。CLI RPC 保留为可选兼容后端。代价：要维护 Adapter/fixture。验证：Mock/Pi 可驱动同一 UI。

## ADR-003 · 产品状态与原生 Session 分权
建议采纳。SQLite 管产品、Pi 管 transcript；消息展示索引可重建，不双写模型消息树。验证：Fork/Compaction/恢复后产品索引可重建且不改写原生记录。

## ADR-004 · 四阶段资源生效
建议采纳。安装、启用、授权、加入 Run 各自有状态。运行以不可变 ResourceLock 固定。代价：界面更明确但实现更复杂。验证：更新/卸载不热改活动 Run。

## ADR-005 · 市场先内容包，后可执行生态
建议采纳。P1 选编 Skill/Template/Preset，不开放任意 Node 扩展一键执行。代价：生态兼容范围暂时较小。验证：安装零 lifecycle 脚本，危险包被拒绝/隔离。

## ADR-006 · 受控本机不宣传强沙箱
建议采纳。审批与 Broker 约束宿主工具；任意 Shell/扩展的强边界必须靠 OS/VM/容器。验证：UI 明确执行环境，策略要求隔离时不能静默降级。

## ADR-007 · macOS 先闭环、Windows 同期竖切
建议采纳。先验证 UX，同时在架构阶段解决 Windows 高风险项。客户画像改变可调整次序。验证：Windows 中文路径、Shell、Job Object、安装包在 G0 通过。

## ADR-008 · Artifact 是一等数据对象
建议采纳。注册必须核实文件/Blob、hash、来源和校验结果；不能解析聊天中的路径就算完成。验证：缺失文件、重复注册、外部修改、历史版本与安全预览。

## ADR-009 · 默认显式启用资源与账户
建议采纳。未审核项目内容不能自动安装包或扩大权限；首次启动不直接共用用户全部 Pi 配置。验证：负向 fixture 确认默认资源发现不带入隐藏扩展。

## ADR-010 · 本地优先、云服务最小化
建议采纳。产品任务保存在本地；选编市场可在线，模型与 Connector 请求按用户配置出网。自动化后续增加 Daemon。验证：无产品云账号也可处理本地任务，离线状态与数据去向明确。
