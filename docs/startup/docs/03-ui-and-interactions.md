# 03 · 信息架构与交互规格

版本 0.1｜该文档是交互草案，非最终视觉设计稿。

## 1. 导航结构

主导航只保留：任务、工作区、技能库、市场、连接器、设置。专家、探索和自动化在能力可用时出现，不在 P0 显示无功能的占位页面。Coding/Work 模式共享页面，仅改变默认 Inspector。

```text
全局导航 | 工作区与线程 | 主工作区：时间线 / 成果画布 | 检查器
                        输入框 / 队列
                        可收起终端 / 日志
```

默认优先阅读空间。侧栏建议 240–300px，检查器 340–460px，可拖动；这只是初始设计参数。窄屏将检查器收起，不能把所有列同时挤进 1024px。用户手动切换后，Agent 不应反复抢走面板焦点。

## 2. 页面及数据

| 页面 | 必须展示 | 主操作 | 错误/空态 |
|---|---|---|---|
| 任务首页 | 等待审批、运行、失败、最近成果 | 新任务、继续、查看问题 | 无任务显示 3 个示例入口 |
| 工作区 | 目录、运行环境、线程、Git 可用性 | 打开目录、新 Thread | 路径缺失、环境不可用 |
| Thread | Run 时间线、当前动作、输入框 | Send、Stop、审阅 | 中断、模型配置失效 |
| 技能库 | 已安装资源、作用域、版本、有效状态 | 导入、编辑副本、测试、启停 | 缺依赖、冲突、待授权 |
| 市场 | 类别、搜索、可信来源、兼容性 | 详情、安装 | 离线显示缓存和更新时间 |
| 插件详情 | 作者、版本、组成、权限差异、平台要求 | 安装、升级、回滚 | 不兼容、撤销、校验失败 |
| 连接器 | 服务、具体账户、权限、健康状态 | 连接、重连、断开 | 过期/限流/只读受限 |
| 成果 | 类型、预览、版本、来源 Run | 打开、导出、继续编辑 | 不支持预览、缺失或修改 |
| 设置 | 模型、执行环境、权限、存储、更新 | 诊断、导出日志、清理 | 不显示长期密钥明文 |

## 3. Thread 页面

Header 展示项目 / 线程名、Workspace、运行环境、执行模式和状态。模型、推理等级与技能选择靠近 Composer；只展示所选模型实际支持的选项，不硬编码所有等级。

时间线以一次 Run 为聚合单元，包含用户目标、Agent 摘要、工具活动、审批与结果。连续读取文件可合并，错误命令与改动默认可见。工具卡保留“原始详情”用于诊断，但默认展示命令、cwd、目标文件、状态、退出码和耗时。不要伪造百分比进度或“正在思考”的内部内容；推理展示仅使用 Provider 实际返回且允许展示的内容。

工具渲染使用自有 Registry：文件、Shell、Diff、测试、连接器、成果、未知工具 fallback。`tool.snapshot` 替换展示，`message.delta` 追加文本。渲染队列与原始事件消费分离，避免大日志阻塞界面。

## 4. Composer

支持文字、文件/图片附件、@文件、/技能、模型切换和 Send。运行期间区分“调整当前任务”和“完成后执行”；后者存 App Server Queue，形成独立 Run。Stop 不删除已排队文字，提供恢复至输入框的入口。

文件选择表示“引用上下文”，不等于给出全盘权限。附件先进入受管理 Blob Store，模型看到的是受控引用。Skill chip 展示其版本、来源、当前是否真正生效；“已安装”不能误显示成“已加载”。

## 5. 审批体验

每条审批卡包括请求来源（Run / 插件 / Connector）、具体目标、动作、参数摘要、数据将发往何处、不可逆风险和有效范围。默认操作是“拒绝 / 仅本次允许”；持久规则需要独立确认，不放一个容易误点的“永久允许所有”。

审批与参数哈希、目标路径规范化结果、包版本、runtimeEpoch 绑定。审批之后目标发生变化必须重新请求；窗口关闭时保持待处理或按策略超时，不能按默认允许处理。后端才是权限裁决者，前端隐藏按钮不构成安全控制。

## 6. 市场安装与技能启用

市场卡片：名称、简述、资源类型、作者、审查状态、平台兼容性。详情页先展示内容与权限，再展示安装。徽章分别表示“签名来源已验证”和“内容已审查”，不使用一个含糊的“绝对安全”图标。

```text
搜索 → 详情 → 选择安装作用域 → 内容/权限确认
     → 下载与校验 → 安装完成 → 选择启用范围
     → 连接缺失账户 → 测试 → 加入一个新任务
```

安装完成不能立即执行 Skill。一个插件含多个资源时，可单独启停技能、模板或预设；具有代码依赖的资源显示依赖约束。卸载前列出受影响的预设与自动化，历史 Run 仍显示它使用过的版本。

## 7. 技能编辑与测试

采用元数据表单 + SKILL.md 编辑器 + 资源文件树。内置/市场原版只读；编辑操作创建个人副本，保留来源和上游版本。测试面板选择固定输入、模型、权限和目标目录，显示已读技能正文、工具调用、输出校验与成本估算。

“创建成功”仅表示草稿保存，“测试通过”来自断言结果，“已发布”表示可供新任务选择，三者分开。测试不能偷偷在当前用户项目执行，默认临时工作区。

## 8. 成果与 Diff

Artifact 是独立对象，不是普通附件。先支持 Markdown、文本、图像和 CSV；Office 预览后续增加。成果显示创建者 Run、版本、路径是否仍存在、是否被外部程序修改。用户点击“继续编辑”新建 Run 并传入版本引用，不覆盖历史成果。

代码默认显示 Last Run Changes 与整个 Workspace Changes 的区别。用户原本的未提交修改不能被算成 Agent 的全部产出；开始 Run 先记录 baseline，结束再对比。Discard 必须预览并确认，不能靠会话 Fork 回滚文件。

## 9. 无障碍与跨平台

macOS 使用 Command 快捷键，Windows 使用 Control；组件读屏名称包含状态。支持键盘审批、可见焦点、中文输入法组合态，禁止在 IME 组合尚未结束时 Enter 发送。深浅主题满足可读对比，不只靠颜色表达成功失败。

日志支持搜索、暂停自动滚动、复制脱敏内容；时间线虚拟化不能让滚动时焦点消失。检查器可以建议跳转，但用户主动固定面板后不再自动切换。

## 10. 交互验收

离线市场必须标记缓存时间；不兼容插件不可安装或明确进入隔离草稿；断开 Connector 不删除历史成果；更换线程不会中断其他任务；审批超时能明确解释；Stop 等到后端确认再显示完成；错误页面有重试/诊断路径但不自动重试外部写入。

参考分工：pi-gui 的工作台与窄 IPC、OpenPi 的 authority 边界、Picot 的内置 Runtime 与会话体验、Pi Desktop 的资源管理理念 [S11–S14]。这些是设计借鉴，不意味着直接合并代码或兼容其全部插件 UI。
