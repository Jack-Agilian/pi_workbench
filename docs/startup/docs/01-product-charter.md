# 01 · 产品章程与首版范围

版本 0.1｜2026-09-07｜设计建议，待团队评审。

## 1. 产品定义

让用户把一个本地项目或文件任务交给 Agent，观察执行，做出必要审批，审阅差异或成果，并把成功方法沉淀为可复用技能。产品不是 Pi TUI 的皮肤，也不是先实现一个完整 IDE。

首要用户假设：能够选择本地目录、理解任务输入输出的开发者与技术型知识工作者。尚未假定已有企业客户、团队规模、预算、收费模式或首发渠道；相关判断需用首批试用验证。项目目录同时容纳 Git 仓库与普通文件夹，Git 不得成为创建任务的必要条件。

两类模式共享同一运行时：**Code 模式**强调仓库、测试与 Diff；**Work 模式**强调文件输入、技能、结构化结果与成果预览。模式只切换预设和默认面板，不维护两套任务数据模型。

## 2. 三条核心用户旅程

**修复代码。** 打开项目 → 选择当前目录或 Worktree → 描述问题 → 检查 Agent 活动 → 审批必要命令 → 查看修改与测试 → 接受结果。Git push、发布和删除不自动随“任务完成”执行。

**整理文件成果。** 选择授权目录 → 选择“周报整理”技能 → 添加材料 → 生成 Markdown / CSV 或受支持的文档 → 在成果面板预览 → 用户导出。生成成功与导出成功分别记录；预览不能执行材料内的脚本。

**复用工作方法。** 在技能库创建草稿 → 输入样例 → 在测试线程执行 → 查看结果 → 发布到个人技能库 → 下个任务选择该版本。模型可生成草稿，不能自行发布、安装或提权。

## 3. 功能与 WorkBuddy 的对应关系

WorkBuddy 官方公开资料可确认技能市场、专家中心、连接器、探索、自动化、记忆、模型设置和成果工作流的产品入口 [S17–S21]。以下实现栏是本项目设计，不描述对方内部结构。

| 功能域 | 拟提供的用户能力 | 我们的实现 | 阶段 |
|---|---|---|---|
| 任务与会话 | 新建、切换、停止、恢复、关注待处理项 | Project / Workspace / Thread / Run + 事件流 | P0 |
| 代码审阅 | 文件改动、命令结果、测试状态 | Git 适配器 + Changes 面板 | P0 |
| 技能库 | 查看、导入、启用、选择技能 | SkillService + Run 资源锁 | P0 简版 |
| 技能/插件市场 | 发现、详情、安装、更新、卸载 | Registry + PackageInstaller + 审核 | P1 选编版 |
| 成果查看 | 预览、版本、来源、导出 | ArtifactService + 受限预览器 | P0 基础；P1 Office |
| 专家中心 | 选择有专长的任务配置 | AgentPreset：指令、技能引用、模型偏好 | P1 |
| 连接器 | 连接账户、选择数据源、调用工具 | ConnectorBroker + MCP/原生 Adapter | P1 |
| 探索/案例 | 用案例创建自己的任务 | Recipe：示例输入 + Preset + Skill 锁 | P1 |
| 自动化 | 定时运行、查看历史、处理失败 | Schedule / Job / Run，显式执行条件 | P2 |
| 记忆 | 用户可查看、修改、删除的偏好 | MemoryItem；区分规则与检索材料 | P1 手动；P2 辅助 |
| 远程助手 | 通过外部入口发任务 | 身份校验 + 任务 API + 单独审计 | P2 以后 |

“探索”不是另一个技能市场：它发布的是输入、配置和成果示例的组合。WorkBuddy 的公开说明也将其与技能、专家区分 [S18]。

## 4. MVP：P0 必须交付什么

P0 以一个模型 API Key 接入、一种经过验证的 macOS Shell 配置开始，但保留 Provider Adapter；Windows 技术竖切同期完成。正式 Beta 前补齐 Windows 用户流程。无需注册产品云账户即可处理本地任务；调用远程模型仍需网络与有效授权，不能把“本地优先”宣传成“数据绝不出设备”。

| P0 模块 | 最小内容 | 不包含 |
|---|---|---|
| 首次启动 | 模型配置、运行环境诊断、打开目录 | 订阅 OAuth 全覆盖 |
| 执行闭环 | 流式回复、工具卡、Stop、审批、失败/恢复 | 任意第三方扩展自动执行 |
| 工作台 | 项目/线程、主时间线、Changes/Artifacts、终端 | 完整 IDE 调试器 |
| 数据 | SQLite 产品状态、Pi 原生会话、导出/删除 | 多设备自动合并 |
| 技能 | 3 个审核内置技能、导入预览、作用域、显式选择 | 用户公开上传 |
| 成果 | Markdown、文本、图像、CSV 表格基础预览 | 任意 Office 文件在线编辑 |
| 安全 | 最小 IPC、凭据隔离、受控本机模式、明确风险说明 | 自研跨平台强沙箱 |

内置技能建议：代码审查（不改代码）、材料周报（输出 Markdown）、表格说明（只读样例 CSV 并生成摘要）。真正执行命令与读写权限由宿主工具控制，不由技能描述决定。

## 5. P1 与 P2

P1 分两批：先多任务/Worktree、选编市场、版本更新、成果索引；再第一个只读连接器、专家预设、一个 Office 输出链路。公开第三方可执行扩展不随市场首页一起上线，需单独安全门槛。

P2 才增加本地计划任务、独立后台服务、远程执行、受限多 Agent 和企业私有源。付费插件、分成、开放投稿、全面 Computer Use、自由工作流画布均独立立项，不列入默认交付承诺。

## 6. 评价标准

把“成功”定义为可验证结果，而非出现一段最终回复。代码任务需记录测试是否运行、退出码与审阅状态；文档任务需记录文件可打开、输出结构校验与预览是否通过。

以下是拟定的验收目标，不是现有性能：相同输入事件重放得到一致 UI；100 次模拟取消无遗留子进程；包安装故障不会破坏旧版本；跨线程事件不串线；已授权写入之外没有被隐藏执行的宿主工具。性能基准记录设备、工程规模、模型延迟，不用首 token 延迟衡量纯 UI 性能。

## 7. 产品边界

用户关闭窗口不等于停止任务；必须由宿主明确提示“继续驻留”或“停止退出”。应用退出后 P0 不继续定时运行。操作系统睡眠、网络断开、进程崩溃不能承诺“无缝续做外部操作”。恢复时展示中断点和未知结果，禁止重复发送邮件、重复发布等有副作用动作。

首版方向：**先把任务交付做可靠，再把技能复用做顺畅，最后建设生态。**
