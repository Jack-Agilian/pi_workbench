# 05 · 技能库管理与 Pi 集成

版本 0.1｜目标：让技能可以发现、选择、解释、测试和复现，而不只是扫描一个文件夹。

## 1. 标准与兼容边界

技能目录采用 Agent Skills 的 SKILL.md + 可选 scripts/references/assets 结构；标准要求 name 与 description。Pi 实现该标准并具有自己的宽松校验和扩展字段，按需读取正文 [S06][S10]。产品公开发布包采用更严格的可移植子集，导入其他 Harness 技能时展示兼容性诊断，不声称零修改全部可用。

技能是任务方法和资源，不是一个必然能独立执行的 API。脚本需要运行时、依赖和权限，连接器需要账户授权，提示模板不能自动获得这些能力。

## 2. 数据模型

```text
SkillDefinition: 稳定身份、资源 ID、来源、作者
SkillVersion: 内容哈希、packageVersion、兼容要求、测试报告
SkillActivation: profile/project/thread 作用域和开关
SkillDraft: 本地可编辑草稿、baseVersion、未发布修改
RunResourceLock: 本次选择的精确版本与有效权限
SkillUsage: discovered / selected / loaded / invoked / outcome
```

Installed、Enabled、Available、Loaded、Executed 分别展示。Skill 可能仅进入可选目录但未读正文，也可能读了正文但未调用脚本。不能用“进入 System Prompt 的摘要”计作一次成功使用。

## 3. 导入与编辑

支持本地 SKILL.md/目录、经过验证的压缩包、选编市场；Git/npm 导入由 PackageInstaller 处理。导入前预览名称、用途、包含脚本、外部依赖、目标平台与来源。导入后默认保持停用；内置审核技能可按首次启动策略预选，但需清楚展示。

市场和内置版本不可直接编辑，点击编辑创建个人副本。副本记录 sourcePackage、sourceVersion、baseDigest；上游升级时比较原版/个人版/新版，不覆盖用户修改。导出只包含技能必要内容，不打包用户输入、测试密钥和缓存。

## 4. 作用域与冲突解析

| 范围 | 用途 | 覆盖规则 |
|---|---|---|
| 组织策略（P2） | 禁用、强制版本、允许来源 | deny 优先，用户不可扩大 |
| 用户 Profile | 默认可用技能集合 | 可由项目缩小/选择其他版本 |
| Project | 项目特定技能与兼容约束 | 明确覆盖同资源 ID 的用户选择 |
| Thread | 临时勾选与固定版本 | 对下一次 Run 生效 |
| Run | 不可变实际版本快照 | 运行中不改变 |

同名不同来源不默默覆盖：主键为 packageId/resourceId，UI 要求选择别名或只启用一个冲突名字。在送入 Pi 前生成唯一 name 的资源投影，并保留原始身份映射。不能依赖文件扫描顺序“先遇到谁就用谁”；Pi 当前自身的名称冲突行为不作为本产品规则 [S06]。

## 5. 从技能库到运行时

```text
已安装不可变资源 + 用户/项目/线程选择 + 组织与运行环境策略
                         |
                    SkillResolver
                         |
           可用资源清单 + 不可用原因 + ResourceLock
                         |
          Run-scoped 只读投影目录 / Custom ResourceLoader
                         |
             Pi 看到名称、描述、受控路径
                         |
            按需读 SKILL.md 或显式 /skill 调用
```

使用自有 ResourceLoader/受控投影，而不是无条件读取用户全局 `.pi`、祖先目录、项目声明的扩展和 package 源。SDK 默认发现包含多类资源 [S02]；关闭某类技能发现不代表其他入口自动关闭，测试必须覆盖 context files、extensions、packages 和相对路径。

从 UI 点击技能时，Adapter 用锁定版本提供的技能调用或确定性 prompt 展开方式载入；不能仅在自然语言里写“请使用该技能”就把它标记为 Loaded。真正正文读入事件要记录资源摘要。用 Pi 标准 read 时只读包投影和授权输入，禁止路径逃逸。

## 6. 按需加载与上下文预算

默认只提供当前任务候选技能的名称和简述，正文在选中后加载；引用文档与脚本按需读取。技能数量大时先按任务类型、平台、账户授权和显式选择过滤，再做检索，不把整个市场塞进上下文。候选上限为可配置策略，首版可用小规模固定集合，不必先上向量检索。

资源加载记录来源/哈希/版本，不要求永远重复插入全文。压缩后重建时保证能重新取得同一版本，而不是继续访问已经更新的可变文件。禁用技能只影响未来资源选择，不能抹掉现有 transcript 中已经读过的内容；需要清洁上下文时创建新 Thread 并明确提示。

## 7. 执行权限

Skill 不能修改 Permission Policy、安装其他包、打开任意新 Connector，或静默把资料发往外部。若任务确需额外能力，宿主展示缺失能力并发起独立审批。`allowed-tools`、兼容性说明、正文中的“已获批准”都不是授权证据。[S07][S10]

禁止技能要求的初始化动作在导入时自动执行，例如 npm install、下载二进制、修改 Shell profile。这些动作属于可执行依赖准备，进入专门沙箱或人工批准流程。多平台技能优先引用 Python/Node 受控工具，而非在正文内写死 macOS 路径；依赖缺失时显示 unavailable，不暗中提权安装。

## 8. 技能库 UI 字段

列表：名称、来源、当前版本、作用域、是否可用、最近测试、更新时间。详情：用途、输入输出、文件树、权限、连接器需求、平台矩阵、历史版本、测试报告与更新差异。过滤器：内置/个人/市场、已启用/待授权/缺依赖/不兼容。

编辑器允许填写 description、修改 SKILL.md 和参考文件；高级文件操作仍遵守包边界。删除一个副本不影响原包；卸载一个包要提示其提供的全部资源。可用“为什么本任务不能用”解释器列出策略、缺账户、平台不匹配和同名冲突。

## 9. 测试与发布

每个技能准备最小 fixture：正常输入、缺数据输入、含恶意指令的材料、跨平台路径、输出结构、禁止行为。测试记录精确模型、Provider、Pi/Host 版本、ResourceLock、工具轨迹、断言结果与预算。模型输出具有随机性，单次通过不证明稳定可用。

代码审查技能要求不修改文件；周报技能要求只引用提供材料、不虚构数字；表格说明技能要求正确声明缺失列。使用明确断言和人工审阅，不用另一个 LLM 的“看起来很好”作为唯一门槛。

发布流程：草稿 → 静态校验 → 测试 → 人工确认 → 个人版本。团队或公开市场发布再加作者、许可证、依赖审查与签名。产品必须限制 Agent 仅能写草稿，不能给自己发放“已审核”状态。

## 10. 验收条目

同名技能不静默覆盖；导入不运行代码；禁用不会污染新 Run；运行中更新不改变 ResourceLock；旧版可重建；个人副本升级不丢改动；缺少描述/非法路径有诊断；用户选择技能后能解释是否读入；技能不能改宿主权限；日志和导出不含 token。
