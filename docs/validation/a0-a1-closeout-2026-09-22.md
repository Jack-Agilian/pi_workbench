## 阻塞复现与修复

开始时先运行 SSOT、工具、结构三项原有检查，均 exit 0；应用严格类型检查复现 42 条上游诊断。相同配置对照如下：

|---|---:|---:|---|
| 原始依赖，TypeScript 5.9.3 | 41 | 1 | exit 2 |
| 原始依赖，TypeScript 6.0.3 | 41 | 1 | exit 2 |
| 原始依赖，TypeScript 7.0.2 | 41 | 1 | exit 1 |
| 增加 MCP peer，TypeScript 7.0.2 | 41 | 0 | exit 1 |
| MCP peer + 固定声明补丁，TypeScript 7.0.2 | 0 | 0 | exit 0 |

因此保留 TypeScript 7.0.2、strict、NodeNext、完整声明检查。没有 skipLibCheck、any/ts-ignore 兼容层、类型 shim、内部 deep-import 或源码条件入口。

补丁只将每个 `*.models.d.ts` 的 `import values` 改成 `import type values`，保留 JSON 推导出的类型。41 个文件、两个安装副本；完整文件清单与修改前后 SHA-256 在 [补丁清单](../../patches/pi-ai-0.87.0-json-types.json)，普通 unified diff 在 [补丁文件](../../patches/pi-ai-0.87.0-json-types.patch)。Git apply 负责应用，不另写补丁算法。

上游 shrinkwrap 遗漏嵌套 pi-ai 的 SRI，本轮根锁补齐与同版本、同 URL 官方 tarball 一致的 integrity。两个副本都必须通过此检查，不修改上游 shrinkwrap。npm ci 之后显式应用已审核的本仓库补丁；不使用 postinstall。typecheck 只检查已安装状态，不偷偷修补。补丁版本、摘要、文件内容漂移及部分补丁均失败。

修复过程中实际发现并处理了本地 diff 生成器遗漏“文件末尾无换行”标记、嵌套锁缺失 SRI 两个问题；错误先失败，没有降低断言。最终补丁 SHA-256 为 `57c11da43fd28c77389c4561b08cadca3706d8181cdd5c11e3eaf6d1bccf266e`。
