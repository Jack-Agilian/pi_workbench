# 单个 LLM 请求的流式超时修正

基线 `bb90b75c09806d4303f312330ff38f40b79e15e3`，实现及全部本轮回归提交见[输入摘要](m1-stream-timeout-inputs.json)中的 `testedCommit`（`ba9b8ea`）。同一功能分支 `codex/m1-resume-policy`。macOS 27.0 arm64 / Node 24.21.0 / Pi 0.87.1，无依赖升级。

## 问题与修正

用户指出：**同一个 LLM 请求，从首个 token 到生成结束，可能超过10分钟**。之前虽然引用了 Pi 的5分钟 HTTP 空闲默认值，产品却同时把5分钟设成总执行上限，连续生成也会被截断。前轮短请求恢复/取消的成功事实保留，但不能证明长流策略正确。

现在区分：

| 配置 | 新模板 | 语义 |
|---|---|---|
| httpIdleTimeoutMs | 300000ms | 等响应头或下一段非空网络数据的空闲上限；有数据到达后下次等待重新计时，不累计生成时长 |
| timeoutMs | 1800000ms | 同一个 LLM 请求的独立总上限，包含等待响应和流式生成，可显式调整至24小时；不是 Pi 默认值 |

参考 [Pi 0.87.1 官方设置](https://github.com/earendil-works/pi/blob/v0.87.1/packages/coding-agent/docs/settings.md)，5分钟是 HTTP header/body idle 默认值。这里的30分钟总上限是产品选定的可配置默认值；持续输出仍受这个明确总上限约束，不宣称无限生成。

宿主 ModelHttp 在待完成网络 I/O 上计时；超时中止拥有的 fetch/reader，关闭释放计时器。空 chunks 不制造进展，SSE心跳/思考事件等真实网络字节属于进展。下游背压没有发起网络读取时，不将消费者等待误判成网络空闲。Pi 继续负责 Provider/SSE/Session，未自写协议或Agent Loop。SDK请求上限使用独立总期限；宿主总截止另加5秒启动余量。Worker ready、取消、guardian清理逻辑保持各自边界，宿主监督接受显式长请求期限。

Renderer 同时显示空闲等待与单个LLM请求总上限。配置解析、策略摘要、修订入口及续验计划包含可选 idle 字段；更改两个时间字段均需显式修订，其他授权字段不得改变。缺少 idle 字段的历史配置保留原总上限，并用旧值作为idle兼容值；其摘要不因升级自动改变。旧用户配置仍为已耗尽4/4的授权，未修改配置、未追加额度或真实请求。

## 集中验证

12条命令一次集中运行全部通过，完整命令、时间及日志摘要在输入JSON；原始输出在 `.artifacts/m1-timeout-20260929/regression/`。

- typecheck；模型集成39项、续验11项、网络/配置、Worker51项、桌面19项、实际Electron离线模型界面。
- SSOT、脚本工具、文档结构与完整示例类型检查。
- 一个合成 HTTP 请求每30ms产生字节，持续12段，在120ms空闲阈值下运行约384ms并正常完成；不是多个短请求拼接。
- 实际公开 Pi Provider →真实Worker/IPC→宿主fetch 的单个合成SSE请求，每80ms送一个事件，总流长超过配置的250ms空闲值并完成；次数预算仍在重开后生效。
- 无响应头、首段之后停止、不断产生空chunk均按空闲超时失败；关闭取消pending I/O且释放计时器。
- 既有独立总截止终止活跃生成、对账不重发用例通过；显式时间修订仍保留原次数/预留，拒绝扩大非时间权限。

这是缩短时间尺度的确定性行为验证与实际离线SDK/进程接缝，**没有执行超过10分钟的真实模型请求，也未新增真实调用**。本轮没有重跑整套A1–A4/Shell/退出矩阵，不将前轮结果当作本轮重跑。
