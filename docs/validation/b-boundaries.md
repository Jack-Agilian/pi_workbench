# B 最小核心的可复现边界

阶段范围说明：本文保留 B 模块级交付当时的限制与 schema v1 记录；后续实际 Worker、schema v2 迁移与 macOS 进程监督的新增证据见 [B-IPC](b-ipc-2026-09-23.md)，不由本文旧合成输入推导。

对应代码：`61ad838ea601ef22f114a44ea533d3aff91517f0`。运行 `npm run test:product-core`、`npm run test:product-sdk`；输入/命令见 [报告](b-2026-09-22.md)，当前契约见 [B 最小契约](../ssot/b-minimal-contract.md)。

## B-G01：Node SQLite 的文件访问不由 Node 白名单阻止

Node 24.21.0 实际 DatabaseSync 在 Node `--permission` 只允许 SDK/受管理测试目录读写时，仍能创建允许目录外的空 SQLite 文件。最初测试期望 ERR_ACCESS_DENIED，却得到成功；只生成本轮自己的空文件，已清理，没有访问真实用户数据库或凭据。

受控复现步骤：准备两个独立临时目录，父进程在第二个目录创建并验证合法的合成 SQLite；子 Node 的文件白名单只允许第一个目录。比较普通 fs 访问与 DatabaseSync 访问，不能假定两者有相同边界。这是 SDK 之外的运行时 I/O 接缝，不通过修改 Pi 修复。

本轮措施：B 启动器除原有 Node 权限/网络 tripwire 外，强制使用 macOS OS 文件规则。合法 canary DB 的只读打开被拒绝，禁止目录中新 DB 创建被拒绝且父进程确认没有新文件；允许的临时目录中真实产品 DB 仍读写成功。其他平台 B 测试明确失败。没有开启 addon、子进程或任意文件权限来绕过错误。

该 profile 允许测试代码、所选工具链和必需系统库，以及受管理临时数据；不是任意扩展的生产沙箱。宿主可信目录策略、真实 Worker 的 OS 监督与 Windows 方案仍待实现。未对外发送 Issue，未 Fork 或修改 Node/Pi 运行时。

## B-G02：状态已持久不等于外部动作已发生或已经结束

派发在事务提交后返回 starting；若调用方在执行前/后中断，重开不会自动重发。核心测试模拟未结算操作与进程重开，将 Run/操作变为 unknown；迟到事实或显式对账仍归原 operation，确认清理后才释放全局名额。

`piIdle/hostClean` 是可信宿主端口的证据输入，测试使用明确合成值；没有把布尔参数本身称作实际进程清理。真正 Worker 启停、超时、退出确认、IPC 认证及替换三类失败的产品恢复仍需连接 A1/A2 已测入口。现在唯一索引作用于同一个产品数据库；两个不同数据库的宿主不会自动互斥。

## B-G03：成果索引只证明一次受控文件观察

产物必须来自已成功操作的相同目标/写入 hash；原操作后的外部编辑不能再次冒领同一 operation。读前后 stat 与限长/no-follow 检查能够发现已测试变化，但祖先路径检查和 open 仍非原子，文件更新和 SQLite 提交也无跨资源事务。发生提交失败时文件可能已存在，应通过原操作/真实文件对账，不能自动重写文件。

当前只返回有限 UTF-8 Markdown 的纯文本。UI 必须用安全文本/已审核 renderer 消费，不能直接当 HTML；缺失和变化有明确状态。其他格式、另存为、可编辑预览、原子 containment 和恶意外部写入竞争未验证。

## B-G04：事件、协议与部署仍是有限模块能力

命令有限字段校验和 requestId 幂等不等于 IPC 来源认证。订阅是宿主内部的同步回调与持久 cursor，跨连接变化需 poll；没有网络传输、异步客户端确认、事件裁剪或故障注入到真实进程。核心不存 Pi 消息，观察投影只保留类型/来源标签；它不是完整 timeline 展示索引重建。

使用 Node 24.21.0 的 SQLite 1.2 候选公开入口是本轮明确采用决定。schema user_version=1，不支持静默升级；未知版本拒绝打开。本轮没有用户旧数据库迁移、OS 掉电、多进程压测、打包 ABI 或 Windows/Linux 证据。若后续选择成熟 SQLite binding，先核对公开发行、原生模块与禁脚本安装路径，再制定迁移，而不是为本轮增加数据库框架。
