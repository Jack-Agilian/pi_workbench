## 复用与必要新增

Pi 0.87.0 的公开 `createBashToolDefinition` / `BashOperations`、现有 controlled-tools、参数验证、Session/Runtime 和结果处理保持复用。公开 Operations 返回退出码而不提供跨 Worker 死亡的持久进程监督句柄；已安装发行包的本地后端在 POSIX 使用 detached 组，D1 的 Worker 组证明不能直接覆盖。此次仅把 Operations.exec 委托给既有 guardian 内约 80 行的单 Shell 生命周期模块，固定系统 Bash，使用 Node 公开 spawn/StringDecoder；不改 Pi 源码、不 deep-import、不替换全局 spawn，不复制 Shell 语言或 Pi 工具算法。

Context7 核对 [Node 24 子进程文档](https://nodejs.org/docs/latest-v24.x/api/child_process.html) 的 detached、exit/close 语义，以及 [Pi 官方 Operations 扩展模式](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md)。文档 main/当前索引只作资料，实际 API/类型/执行仍以安装的 0.87.0 为准；查询中的其他 Harness 示例未采用。

必要产品增量是判别明确的文件/Shell ExecutionPlan、单次 exec/有界结果消息（IPC v4）、Operation 下的意图/结果投影（SQL v5）、纯文本工具卡与审批、两个固定演示及测试。App Server 仍是产品 SQLite 唯一写入者，guardian 只写宿主保护目录的收据，Worker 不导入 ProductCore、不增加 child_process/addon 权限。没有新增依赖，唯一锁、声明补丁、初始化逻辑和 startup 快照未变。

## 已验证链路与边界

宿主先选择命令、cwd、profile、环境策略、timeout 与期限，摘要同时绑定 Pi 实际参数、Run/runtime 身份和实际 workspace。Renderer 只选择固定演示及批准；请求不能携带自由 executable/env/数据库路径。批准一次领取后 Worker 的真实 Pi 工具经 Operations 请求执行，宿主再次核对计划/取消/期限/资源，guardian 才启动自己拥有的 detached Bash 组。

Bash 正常 exit 与后代清理分开；取消、超时、Worker/宿主死亡都由 guardian 停止 Bash 与 Worker 两组。持久 Shell 收据的身份和 Operation 与原计划核对，正常 cleanup 还需两组消失。未启动有明确收据；已启动则 sideEffects=possible，失败、取消和超时都不表示文件已回滚。无 Artifact 的命令可以完成；命令结果丢失后只对账，异常信号中断且未持久取消/超时的 Run 继续 unknown/blocked，不自动重发。

Shell stdout/stderr 各收集前 4000 字节，StringDecoder 处理分块 UTF-8；超出后仍排空但不积累队列，完成时一次返回有界快照并显示截断标志。不是实时终端/全量日志，也不承诺两路交错顺序。Pi 继续处理接收到的有界输出；传输上限单列，不把它称为上游原始全量结果。现有纯文本投影处理已知敏感格式，但不是通用秘密边界。

实际 OS 限制拒绝 Shell 读取合成宿主文件、收据 canary、资源，拒绝 Node SQLite 读取/创建测试宿主库，且同一程序可在工作区创建 SQLite，排除了“SQLite 根本不可用”的伪通过。还验证工作区 symlink 不绕过目录限制、Shell HOME 不跟随工作区链接、父进程合成 Provider 环境不继承、真实 loopback listener 被拒绝。Shell 的空 HOME 位于单次受管 lease，只开放其子目录，不开放整个 lease。

## 开发期失败与修正

- 首轮 Shell 收据误展开整份 LaunchSpec，严格 exact 校验拒绝，导致三个检查 cleanup_evidence_missing，其中执行用例等待至期限。改为只复制 instanceId/runtimeBindingId/nonce，不放宽收据 schema；随后 18 项通过。失败属于未提交开发树，原日志保留，不作为当前 SHA 成功证据。
- 原 Worker v1 迁移夹具在降级时漏删新增 shell_display，出现 table already exists。修正夹具的历史结构，生产迁移没有改成容忍错误结构，原断言保持；最终 Worker 50 项通过。
- 一次开发期 Electron 输出 helper sandbox-extension 提示，程序化界面检查通过；未改系统权限、关闭沙箱或放宽脚本执行。

最终文档变更后再次执行 SSOT/脚本/结构/完整文档检查，范围和结果记入输入摘要 `documentationChecks`。完整运行回归仍归上述真实代码 SHA，不重跑/冒充未改变的初始化、干净克隆或发行下载核验。
