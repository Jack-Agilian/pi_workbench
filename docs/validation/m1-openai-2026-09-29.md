日期：2026-09-29。基线 `07a845db36aa54ad2496b5208b5b30deea2db975`，当前功能分支 `codex/m1-model-session`；被测实现提交 `fee5da1c08771e607831b754c86b84a310ceb34a`。后续文档提交不冒充被测代码。

## 范围与复用

沿用 Node 24.21.0 / npm 11.19.0 / Pi 0.87.0 / Electron 44.4.5、唯一锁和既有声明补丁。实机 macOS 27.0 arm64，Node arm64，Rosetta=0；Python 3.14.7 使用仓库 .venv。没有依赖升级、全局配置变更或修改 startup 快照。

- 复用 Pi 原生 OpenAI Responses/Chat Completions、公开 ModelRuntime.registerProvider/setRuntimeApiKey、既有 SSE fetch seam、Session 与宿主预算/进程清理。registerProvider 是公开类方法，不是包根导出；无 deep-import、any、ts-ignore、experimental 或上游运行时代码修改。
- 只增闭合的产品 OpenAI 元数据 DTO、宿主 payload 准入、官方/兼容初始化模板、专用 auth.json 字面量读取与离线测试。兼容接口的上下文/价格由用户声明，模板用无效零值要求用户填写，不能假装已核验服务商数据。
- auth.json 沿用 Pi api_key 记录形状，明文且 0600；主机在启动/重连时读取，Worker 仅得当前内存 key。拒绝仓库内、.pi、symlink、公开权限、其他用户所有及超限/非普通文件。只支持字面量，不执行 !命令/环境展开/OAuth；不读取真实全局 auth 或系统钥匙库。临时 .key 选择仍存在，不写回持久文件。
- 正式入口仍是现有 DesktopHost → Supervisor → 受限 Worker → 原生 Pi；未新增 Renderer key/path/execute API。UI 只收到状态。每次请求零工具、禁重试、单 URL、预算预留、取消/清理保持原有边界。

配置端到端测试另发现 describeModel 把完整产品配置展开到严格 ModelSelection 而被拒绝；改为显式挑选 endpoint/openai 字段。新增 HostClient 测试初稿漏掉 connect 已修正。中途类型错误已解决；上述失败原始日志保留在 .artifacts，不作为通过证据。
