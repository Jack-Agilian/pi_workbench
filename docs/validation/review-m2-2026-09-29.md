## R01：BOM 文件的预期摘要与实际字节不一致（P2，已修正）

位置：`apps/agent-server/artifact.ts`、`packages/pi-adapter/file-planning.ts`。

原 `TextDecoder('utf-8', {fatal:true})` 去掉 UTF-8 BOM，但 inspectMarkdown.digest 是原始字节摘要。宿主将去 BOM 的 text 交给 read 摘要/Pi 内存 edit 预演，实际 Pi 工具面对的仍是含 BOM 文件。原 Mac 真实产品链路中：读取最终 failed；编辑已写入后停在 unknown。

修正为显式 `ignoreBOM:true`，保留文本中的 BOM 标记，让经验证的 UTF-8 文本可按原字节重新编码。继续复用 Pi edit 计算，不另写编辑算法；严格 UTF-8、NUL、路径和大小限制不变。新增 read/edit 两条实际 SDK/Worker 回归，检查原始 BOM、文件结果、Artifact 与重开状态。

## R02：只读操作恢复不应依赖今天的文件内容（P2，已修正）

位置：`apps/agent-server/worker-supervisor.ts` 的 recover 文件分支。

原代码在将中断 read 结算 failed 前，先读取当前文件并执行 Markdown/16000 字节检查。实际测试在 read 完成、结果未确认时终止所属 Worker，等待真实清理后再由测试模拟外部编辑：16001 字节或非法 UTF-8 都使 recover 抛错，旧 Run 保持 unknown。

修正后仍先要求原 guardian 清理证据及绑定有效；未知 read 直接结算为 failed，不重新读文件、不发模型请求，也不宣称它从未读取数据。write/edit 仍核验当前字节及原预期结果，不能绕过未确认的写入副作用。新增两条真实 Mac 故障回归验证原文件/mtime 不变、只消费一次模型请求、重复恢复不产生新事件。
