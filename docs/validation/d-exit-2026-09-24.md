## 复用与行为改变

复用现有 runs.cancel、Supervisor.close/recover、guardian 清理收据、原生 Session 引用、Operation/Artifact 对账和受限 Worker。只在 DesktopHost/HostClient/Electron main 补关闭与恢复编排，以及 2 个可信测试驱动文件和稳定测试命令。依赖、唯一锁、声明补丁、初始化器、SQLite schema、Worker IPC 版本、Renderer 权限均未改变；没有新 Harness 或 RunCoordinator。

正常宿主关闭现在先停止新请求/派发，持久取消其 queued/starting/running Run，再等真实清理和文件对账，最后关闭库。cancelling 继续等待；unknown 不伪报 cancelled。已完成成果保留原字节和纳秒 mtime。关闭与显式重连会中止仍活着的旧宿主拥有的工作；若宿主已强杀，取消是否被接受以真实持久记录为准。

关闭失败保留原窗口、提示和旧 HostClient 的共享失败结果。用户通过现有“重新连接”按钮启动新客户端，必须先等旧进程 exit+disconnect；再通过“核验并恢复”读取真实库/文件/收据。候选宿主若与新关闭竞争，主进程等待所有拥有的实例结算，不提前放行或发布迟到实例。没有给 Renderer 新增进程、路径或测试控制能力。

通过 Context7 核对 [Electron 官方 app 生命周期资料](https://github.com/electron/electron/blob/main/docs/api/app.md)；文档 main 仅说明 API，实际执行仍固定 **Electron 44.4.5**。正常退出测试必须经过 app.quit→before-quit→will-quit，由父进程看到 code=0；没有用 app.exit 代替正常退出。SIGTERM/SIGINT 进入同一路径，SIGKILL 则明确是异常退出。

## 真实退出矩阵

外部项目 Node 在独立中文/空格临时目录启动实际 Electron，退出后核对捕获的宿主/guardian/Worker PID、真实收据及进程组消失，再只读打开测试 SQLite。每个场景是一个真实桌面进程；输入、信号和故障选择是明确 SYNTHETIC，未调用模型。

| 场景 | 实际结果 |
|---|---|
| idle | 经过 will-quit，code=0；无 Run/Worker |
| starting / 等待审批 / executing | 原 Run 和排队 Run 都持久 cancelled；只有一次 Worker 派发，无目标文件 |
| cancelling | 原已请求取消的 Run 结算 cancelled；无目标文件 |
| completed | 原 completed 状态、Artifact、文件字节与纳秒 mtime 不变 |
| SIGTERM / SIGINT | 实际信号触发正常退出；活动/排队 Run cancelled，子进程/组消失 |
| Electron SIGKILL | code=null、signal=SIGKILL、无 will-quit；实际 IPC 断开使存活 App Server 完成清理/取消，不能称为正常退出 |
| 缺 guardian 正式收据 | 先失败保留窗口；实际按钮重连后 unknown/blocked。测试恢复 guardian 原样生成的 `.tmp` 收据，显式核验后 cancelled，第二次关闭才正常退出 |
| 领取后出现第三种文件版本 | 实际外部测试写入使对账 unknown；真实清理收据齐全仍不能结算。测试所有者恢复操作前版本，用户核验后 cancelled；没有工具重写 |
| 关闭与新宿主创建竞争 | 真实候选 Node 进程被 SIGSTOP，旧关闭先失败仍不能提前完成。SIGCONT 后候选被回收、不发布；新一次显式重连/核验可正常结束 |

共 **12 场景**。缺证据/不确定版本场景中的文件恢复属于测试所有者的明确操作，不是产品自动修复或伪造成功凭据。原生 dialog 在测试中只截获调用参数，未人工点击；恢复按钮则在实际 React 页面点击，使用原 preload/IPC 链路。

另在 `test:desktop` 中复用既有固定 parent/child Worker fixture，经真实 DesktopHost.close 验证 Worker、guardian、两个后代 PID 消失、心跳文件停止、监听被 OS 拒绝、无意外端口标记；真实重开库后原 Run 和队列均 cancelled、单 Operation failed、无工具文件。仅覆盖固定不脱离进程组的后代，不证明任意恶意进程或已开放网络端口回收。

## 开发失败与修正

- 原桌面回归的缺收据用例按 C 行为期待 failed；新增关闭取消已经持久后，应为 cancelled。测试改为读取实际 cancel_requested：关闭请求被 SIGKILL 抢先打断时仍按真实审计决定结果，不因客户端调用 close 就假定取消被接受。
- 原 v3 迁移 fixture 用 DesktopHost.close 留下 queued；新关闭策略会取消它。改为仅在无 Worker 的测试夹具中直接关闭底层库，构造真正的骤停旧库，继续严格比对原 queued 意图、游标与原生元数据。
- 首轮 cancelling 退出测试在取消完成后才提交第二个任务，第二次派发发生在关闭前，使“一次派发”断言失败。取消中场景现在只验证原 Run；队列关闭由 starting/approval/executing/信号等场景独立覆盖。保留全部 PID/收据/文件/SQL 断言，失败临时目录在独立核对清理后删除，原日志保留。
- 一次开发期 Electron 输出 helper sandbox-extension 提示，程序化检查通过；没有调整系统权限或放宽 sandbox。
