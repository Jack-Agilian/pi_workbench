## 跨区域冲突与优先方案

1. **目录对象混淆（优先）**：NAV.WORKSPACE是新会话目标，HEAD.IDENTITY是已选Thread归属；当选中旧目录会话时二者可不同。目前一个只显示basename，另一个显示整路径，规格仍用泛称目录。方案：新建动作持有目标目录；顶部持有会话目录，两者各有明确名字/全路径入口，不共享可变字段。
2. **新建名称草稿隐形生效**：NAV.CREATE的details关闭不会清title，下一次主按钮仍使用它。现有规格只要求关闭不创建，没有决定是否取消草稿。方案：先新建后改名，或命名面板内有明确新建/取消并将生效范围限制该面板。保持未确认同请求重试。
3. **导航预算不是224px就能成立**：常驻目录/搜索/筛选/清除/结果/加载状态和footer共占高度，load more在nav之外；低高CSS反而把nav设min-height:100。目标“仅列表滚动”与源码退路冲突。方案：搜索/条件简化，读取/分页进入列表，低高不固定100；用非空列表和改名错误验收。
4. **成果覆盖与顶部弹层焦点**：成果覆盖只遮content-grid，HEAD仍可操作；NAV覆盖全应用且inert主区。上下文原生details没有同级/顶层Escape规则。规格“一次只允许一个模态层”没有定义打开NAV时已开成果是否关、隐藏还是保持。方案：建立展示层优先规则；NAV开时成果/上下文不能获取焦点，关闭后恢复原用户选择，Escape逐层关闭，不能据视觉动效另发命令。
5. **断点与可调宽互相牵制**：成果并排开关固定1000，导航固定700，而用户NAV可调到360、成果到640；pane-layout虽限制主区360，但360不足证明长标题+审批/停止/成果及输入200%可用。CSS700含边界、JS<700也不一致。方案：以三栏实际预算/标题工具条最小宽验证阈值；统一JS/CSS边界，保留记忆宽而只夹当前显示值。
6. **180ms宽度动画未解决阅读问题**：规格要求正文锚点保留，却同时逐帧重排正文。现有滚动hook只有一个写入者，应先验证它在宽度变更期间能维持阅读；最小方案可即时重排，覆盖层平移，不能为了动效强行新增第二套滚动恢复。
7. **常驻元信息的用途待证**：NAV短ID、重复basename、loaded计数和健康连接行不能仅因已有规格就保留。设计稿应先隐藏这些，保留同名辨识/分页/故障的按需入口；对照常规、重名、正在执行和离线四态，检查是否仍能识别对象与下一步。

建议成组原型路径：新建/选目录 → 切旧会话 → 搜索筛选 → 改名冲突 → 活动审批/停止 → 成果展开 → 200%/低高。先完成这一组信息层级方案，再修唯一规格并实现。主参考是P1/P2/P4的紧凑行与对象层级；不是照抄其调度/Session/全局导航。
