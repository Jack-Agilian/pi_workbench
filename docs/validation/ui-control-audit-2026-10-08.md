# 全部区域与控件的社区对照审核

2026-10-08；工作树 `worktrees/develop`，分支 `codex/ui-correctness`。审读代码基线为实际存在的 `07ed0897fee696790db16a1eee970f927813decc`。本批只增加审核、覆盖索引与计划/规格入口修订，没有修改产品代码。文档检查对象是该基线加本批差异，不把基线说成已包含本报告。

## 结论

问题不止成果栏。当前界面把持久记录、执行审计和配置字段直接安排成可见空间，再用说明文字解释关系；上一版规格树也保留了这个前提。它能说明“控件放哪里”，却没有先解决“用户现在在处理什么、下一步是什么、哪些信息此刻有用”。仅照树实施，会把现有问题规范化。

本轮按用户指定，实际派发三位 **gpt-6-sol** subagent 分区审查；主代理复核源码、实际参考图及跨区域冲突。每项同时审查现有代码和目标规格，不以符合旧规格作为合理性的证明。70项是覆盖数，不是70项缺陷，也不是设计验收通过数。

## 主代理交叉质疑后的取舍

1. **不把预览变成新的准入流程。** 文档组初稿要求识别“用户明确要求展示”和“唯一主文档”，现有数据并不支持，而且容易再造门槛；已要求其删除。下一步只比较前台任务首次登记自动开一次与点击打开两种原型，保护手动选择/关闭，不在历史补页、重连或后台任务时抢焦点。
2. **不机械搬停止位置。** 输入附近控制虽然常见，但当前右栏能使CHAT不可交互；仅把停止移到输入会退步。位置必须与层级/覆盖共同设计，顶部可达性先保留。
3. **不借精简抹掉两个目录的区别。** 新会话目标目录和当前会话归属是不同对象；同名时省略所有路径也会失去辨识。只删除重复无用字段。
4. **不把临时协议缺口写成永恒布局。** 独立操作区目前保证不伪造顺序，值得保留为旧记录降级；它不是未来聊天阅读必须固定的形态。安全投影需另有明确增量，不能UI先伪装已支持。
5. **社区证据不覆盖用户已定要求。** 会话组最初质疑文字入口是否需要气泡；已修订为保留用户指定“更改权限”，只把精确延迟与状态样式留待验证。
6. **不把每条审查意见自动变成开发任务。** 队列编辑、全文件浏览器、历史字节快照、置顶归档、并发、完整IDE与生成式空态建议都不进入这次改版；只借鉴已需要的行为。

## 下一步单线推进

当前事项仍是“信息层级重构与日常体验复审”。先做一套连贯的状态原型，纠正对象和信息层级，再修改对应树节点并成组实现，不能从70条建议逐个修小控件：

1. **完整设计样例**：选/建会话→输入→排队或执行→批准/拒绝/停止→Chat文档入口→右侧阅读→关面板继续。用合成长中文、同名目录、长命令和文档，不调用产品模型。含正常、待批、权限未确认、断线/未知；宽窗、窄窗、200%及低窗高。比较两种文档打开策略，明确每个空间的主人、滚动和焦点返回。
2. **同步权威树并一组实施**：导航/顶部、消息工具/审批、输入权限、文档阅读/反馈沿上述路径联动。可直接复用现有产品协议的先做；确需可信顺序/消息关联的最小宿主改动单列，不以重写Session解决。保持一套布局、滚动、请求、取消所有者。
3. **集中验收**：状态样例评审与功能回归分开；再验证原生连续操作、键盘/缩放/长内容/动效，记录真实不足。真实模型不用于每个样式修补；既有Gate不因文件数量或自动化通过扩张。

本批只在规格根标明v1待纠偏，尚未把所有候选建议硬写成最终叶节点要求。后续设计变更必须同批维护父子归属；审核报告不成为第二套规格权威。UI-01/02、ART-01保持in_progress，adoption/evidenceRecords不新增“实现通过”声明。
