## 优先问题

1. **P1：权限保存未确认后的原因可能不可见。** L4在失败后 `pending(!resolved)`，L1据此停用发送；summary只有保存中的临时提示，收起后错误/重试隐藏。先把未确认/冲突摘要及同次重试入口保留在触发器旁，再改善面板，而不是只删“权限：”。这是源码确认的状态呈现风险，未做实际点击验证。
2. **P1：任务阅读结构暴露数据容器。** L2始终先正文后操作，L8没有可信跨列表关联。用户问“刚才做了什么、现在卡在哪里、结论是否可靠”，却要自己连接两套内容。CHAT/TOOLS的目标仍将操作固定在 Run 分区，不能当作最终正确模型。短期将正常历史执行折为轻量摘要，待审批/失败/未知保持可见；长期先形成宿主拥有的安全排序/关联投影，再按真实关联阅读，旧记录保留独立区与“不代表正文先后”提示。不能仅排序数组伪造时序。
3. **P1：输入与运行控制的任务语义分裂。** L1发送在底部，停止在顶栏，运行中提交显示加入队列。P3/A1支持的纠正/steer不是本产品功能。应在输入旁明确“将在当前任务结束后执行”，显示已排队项与其取消入口；是否把停止移到输入栏要由 HEAD/COMPOSER共同决定，保证窄窗成果覆盖后仍可达，不能制造两个独立停止状态。
4. **P2：审批是用户决定，却沿用日志容器和嵌套滚动。** L7的 Run 分区包审批，审批自身body滚动，文件preview再次滚动。缩字/缩卡不解决目标、风险和按钮阅读割裂。审批应成为当前待办的展开内容，完整目标/关键风险及决策在同一自然阅读路径；超长输出才局部滚动。
5. **P2：补读把“读更多”变成切换数据视图。** L5有首批 chunks 时原children整个消失，用户/助手摘要替换为原生投影，且每次打开都出现过滤/操作说明。应让同一消息原位补全，或以明确“详细记录”视图切换呈现；方案需要宿主可信消息关联，不能在 Renderer按文本猜测合并。

## 跨区域冲突与成组实施路径

| 冲突 | 需要先明确的设计选择 | 可独立实施范围与业务边界 |
|---|---|---|
| CHAT/TOOLS/SSOT principles把“独立列表不得猜时序”同时写成固定产品空间 | “不能伪造顺序”应是永久边界；“工具只能在Run后面”只是当前DTO不足的降级方式。两者分开维护 | 先减轻正常日志、保留失败/待批；若要可信交错，由Worker/Pi原生公开事件与宿主安全投影提供关联，不在Renderer深导入SDK、重建Session或猜时间。 |
| HEAD停止始终可达 vs COMPOSER自然控制位置 | 决定唯一当前任务停止控件归属；成果覆盖使CHAT inert时，停止若仅在输入会不可操作 | 在顶栏保留停止可达是当前合理约束。可以输入状态处给清楚定位关系/任务状态，而非增加第二套取消状态；移动需一并改覆盖范围与键盘路径。 |
| PERMISSION面板关闭 vs COMPOSER停用发送 | 全局阻断状态必须在关闭面板后仍可发现 | L4确认逻辑不改，只把待核对反馈/重试做可见投影；宿主revision/原intent保留。 |
| FEEDBACK模型配置 vs COMPOSER能力span vs HEAD上下文 | 每个常驻值应帮助本次选择；品牌/工具清单不是可行动上下文 | 模型/能力只一处有效入口；目录主要在HEAD，权限主要在COMPOSER，Run固定值只在活动/审计必要处。不可因UI整理启用更多模型/工具。 |
| TOOLS.APPROVAL/OUTPUT多个内部滚动 vs CHAT单一阅读意图 | 审批目标/风险和决定要在连续阅读路径，长输出才局部滚动 | 取消审批body的常态最大高度，限制仅长预览/输出，并验证长命令/200%/低高度；原timeline锚点、审批焦点接续不重写。 |
| 空态办公建议 vs 有能力的文件/Bash工作台 | 模板来源于具体用户任务/目录，而非看到空runs便生成营销式选择 | 无会话直接新建，有会话直接输入；保留可选择的有限合成演示。模型生成建议属于新行为与费用，不默认实施。 |
| MESSAGES复制/补读 vs 成果复制 | “复制当前展示”“复制已加载部分”“复制核验预览”范围各异，但视觉应统一 | 共用熟悉操作形式和就近反馈，范围事实分别保存，不能复制未加载/已过滤内容，也不能把登记摘要当真实文件字节。 |

建议第一组实现覆盖“新会话→输入→排队/当前执行→待批→完成/失败→继续输入”，同时完成权限未确认外显、输入/正文轴线、正常工具摘要和审批阅读容器。用真实长度中文、同名文件、长Bash、无模型合成记录制作默认/展开/异常样例，然后做现有宿主/权限/身份回归。可信穿插、消息原位补全、队列编辑分别是需先补契约的后续能力，不能以设计卡片先行冒充已实现。
