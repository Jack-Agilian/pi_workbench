## 界面与故障断言

- 实际沙盒 Renderer 中 require/process/通用 send 不存在；非法字段不能进入命令。CSP 下 HTTPS/file 请求失败，HTML 注入文本不生成元素/执行；已知合成 token 从正文和预览移除。源码构建清单确认 Renderer 不导入 Pi、App Server 或 Node 权限模块。sender/frame 绑定由实现审查覆盖，未声称经过任意恶意 Renderer 渗透测试。
- 允许只写一个宿主固定路径并登记成果；拒绝目标不存在；领取后的活跃取消最终为 cancelled，目标不存在。UI 不以取消按钮点击即时宣布成功。
- App Server 被实际 SIGKILL，UI 显示断连；等待实际 guardian 记录 Worker/进程组消失后，经 UI 重连读取原 SQLite，原 Run failed，不创建第二次执行或重写文件。
- 另一个实际 Worker 故障测试在成果提交回调处 SIGKILL，Run 先 unknown；重开库核验原成果，文件内容与纳秒 mtime 不变。B 原有“写入但结果丢失”故障仍由 48 项回归覆盖。
- 每个场景重开真实 App Server/SQLite 后，状态、展示缓存和游标保持一致；事件读取不执行工具。切换 4 个 Thread 检查单 Run 隔离及独立草稿，异步展示受 Thread/请求身份保护。
- 原生 getBranch/appendMessage 输入是合成记录；真正的 write 由已注册 Pi 工具执行。没有手写 JSONL，也没有真实模型流 fixture。v1/v2/v3 数据库迁移和过期绑定不能写展示缓存均有测试。

## 发现的失败与修正

1. npm install 重写 bundled Pi lock 项时去除了既有 integrity，声明补丁检查立即失败。只恢复已有、已验证的同版本 SRI；未改补丁或绕过断言。之后 npm ci 两次与全量发行校验通过。
2. 最初 Electron ESM 入口在顶层等待 ready，导致启动超时；改为普通异步启动函数后实际窗口正常创建。一次 OS helper sandbox-extension 提示也记录在初次日志，未放宽 sandbox 或修改系统权限。
3. 重连等待 ChildProcess close 超时。独立复现显示进程 exit=0、IPC disconnected，但没有 close 事件；修正为同时等待实际 exit+disconnect，无输出管道，并增加真实宿主重开与 close/reconnect 竞态测试。没有用宿主退出替代 Worker 清理收据。
4. 旧迁移 fixture 只回退版本号却保留新 v4 表，产生 duplicate table；正确移除仅新版本的展示表后构造真实旧 schema，保留原意图/引用断言。未把 CREATE 改为宽松忽略错误。
5. Thread 切换 UI 测试初次选择器没有考虑导航图标，补明确可访问名称后通过。最终审查补同步身份遮挡、省略提示、成果来源，并按新 SHA 单独再测。
