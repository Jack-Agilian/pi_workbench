## A1 隔离与真实 SDK 测试

使用真实发行包创建 SDK Session/Runtime；没有 Provider 调用，没有使用 faux/local/free/subscription Provider。tools/customTools 均为空，ResourceLoader 创建时直接返回空集合，未实例化 DefaultResourceLoader 后再过滤。SettingsManager.inMemory、空 InMemoryCredentialStore、InMemoryModelsStore、modelsPath:null、allowModelNetwork:false、refreshOnCreate:false 均显式传入。

每次测试进程使用新的 `<managed-temp>`，HOME、agentDir、workspace、Session 路径独立；Node 文件权限只读所需项目文件/依赖及该临时目录，只允许写该临时目录。禁止子进程、worker 和 native addon，因此系统密钥库 CLI 也不可调用。网络 tripwire 在 SDK import 前加载，拦截 fetch、HTTP(S)、TCP/TLS、HTTP2、DNS、UDP、WebSocket 等常见入口；即使异常被捕获，进程仍以 97 退出。macOS 系统 sandbox-exec 额外拒绝 network*，失败不退回开放网络。此边界防止受信任探针意外调用，不宣称是完整产品沙箱。

5 个独立网络负向子进程均按预期退出 97；文件越界和子进程调用按预期 ERR_ACCESS_DENIED，worker/addon 权限关闭。正常 SDK 进程退出 0。测试数据、环境变量名和故障标签均为合成数据；网络自检没有实际 Provider 请求。
