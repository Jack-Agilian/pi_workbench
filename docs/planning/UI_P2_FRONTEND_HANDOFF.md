# UI-P2 前端增量与接入边界

基线：develop `58d3130d9ed480e283434c749e285efd6ba2092d`。前端分支 `codex/ui-history-artifacts`，按用户明确要求继续使用当前会话工作树；已准备的另一条 `feat/ui-history-artifacts` 不在本次开发范围。不得凭工作目录名判断集成分支。

## 本轮前端交付

- 提取 RunHistory、ApprovalList、ArtifactPanel，保留产品DTO和既有命令身份/确认重试。
- 审批与成果栏可收起，提供紧凑/标准/宽三档；较小窗口受布局约束。主区域保留待审批计数、查看入口和当前执行停止；新审批不自动抢焦点或展开面板。
- 按Thread保存当前浏览位置；跟随最新或保持旧记录锚点；切换会话恢复草稿/位置，提供返回最新。只是已成功传入Renderer的记录浏览，不解决R03超限。
- 成果显示文件名、相对路径、来源输入/执行、版本和字节数。默认当前状态未核验；按需调用既有preview，区分ready/changed/missing/unavailable并标记上次核验时间。迟到预览在关闭或切换会话后失效；不向Renderer开放任意文件接口。

## 分页接入仍待后端提交

本轮不修改packages/app-contracts、main/preload/host-client、数据库或监督器。不自造分页接口/第二套Session历史，不把只渲染部分全量数据称为传输分页。

后续采用后端的同一份已提交契约，具体字段由契约所有者落码：

1. 历史/成果页同时约束条数与字节数；页cursor与事件seq独立，返回一致快照和hasMore。
2. 最新活动Run/待审批独立于所浏览历史页；翻旧页不能隐藏当前审批或停止。
3. 前端加载更早页保留锚点，取消过期页请求结果；切换Thread和重连都隔离请求代次。事件重放只更新展示。
4. 单独按需核验成果状态，不因每350ms轮询而重新读取全部成果内容。
5. 工作区失效等安全错误依据正式DTO展示；不接收原始异常/SDK对象。

本轮仍使用原thread/events接口，R01/R02/R03和开发profile隔离由后端线承接，尚未在此分支修复。真实profile、凭据和费用账本不复制。GUI检查仅用既有临时profile的smoke模式，真实模型调用0。
