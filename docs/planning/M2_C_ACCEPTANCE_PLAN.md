# M2-C：真实有限文件 Agent 验收方案

日期：2026-09-29。状态：**待用户批准的新方案，不是运行授权**。M2-A/B 复审修正见 `docs/validation/review-m2-2026-09-29.md`。本方案不改变 MODEL-03 in_progress 或 M0-Pi blocked。

## 1. 先完成什么

先集成已复测的 M2 审核修正，再准备复用现有 HostClient、产品命令、Pi Worker 和预算账本的显式验收驱动。保留原 M1 驱动，不将其零工具场景冒充文件 Agent 验收。不引入第二套 Provider、Agent Loop、数据库或自动审批服务。

真实调用前必须分别核对：当前代码 SHA、所选 Provider/模型/endpoint、原账本、新授权身份、输入/输出文件范围及费用上限。只读检查不加载 auth.json，不连接服务，不试探 endpoint 背后的实现。不得为检查配置而发送测试请求。

## 2. 待批准额度与权限

| 项目 | 提案 |
|---|---|
| Provider / 模型 / endpoint | 沿用用户已选择的组合，执行前确认，不自动切换 |
| 新增请求总上限 | 最多 8 次真实 LLM HTTP 尝试；工具结果触发的继续调用也计数 |
| 输出 | 每次最多 512 tokens；不足导致失败时停止，不自动增加 |
| 时间 | 单次请求总上限 30 分钟、独立网络空闲 5 分钟；人工审批不算网络空闲 |
| 费用 | 由现有 `describeModel` 计算单次保守预留，再以 8 次计算方案；具体金额待用户批准，不以 SDK 估算替代账单或服务商硬限额 |
| 工具 | 仅 read/write/edit；有效 UTF-8 Markdown、不含 NUL、每文件最多 16000 字节 |
| 每 Run 上限 | 提议最多 6 个工具操作、4 次模型请求；单操作含等待审批最多 5 分钟，均需进入获批准配置 |
| 数据 | 仅本文的合成非敏感资料；不读取项目源码、个人文件或真实业务材料 |
| 审批 | 每个读取、写入和修改单独人工决定；未获逐项批准不执行 |

原 M1 授权 4/4 已耗尽。新授权应明确增加用途/额度，而不是替换 ID 来重获旧额度；不得清空旧 model_requests、修改旧预留或删历史报告。建议继续使用同一真实产品账本，在批准工作区内建立独立测试子目录。不要仅换 profile 就获得同一授权的另一份预算。

方案中的每阶段分配是验收规划，不意味着当前宿主已有独立阶段配额字段。总额与每 Run 上限由现有宿主预留强制执行；需要更细阶段上限时，驱动必须在发送前落实，不靠事后轮询宣称强制限额。

## 3. 场景与证据

受管理测试子目录记为 `m2-c-<attempt>/`，实际名称和根目录在批准时固定。`source.md` 由验收准备创建，只含三个合成条目，例如 alpha=2、beta=3、gamma=5。允许读取它，但拒绝修改它；允许创建/修改 `summary.md`。这些是逐操作审批规则，不把提示词路径限制称作新增 OS 权限。

| 阶段 | 建议请求分配 | 必须观察的事实 |
|---|---:|---|
| 正常文件任务 | 最多 4 | 模型自行提出读取 source.md、生成 summary.md、执行一次明确修改；宿主逐项批准；最终文件与操作审计一致，不预先生成答案或伪造工具调用 |
| 拒绝审批 | 最多 1 | 独立会话请求写入 refused.md，在真实审批上拒绝；未创建该文件，不继续调用模型；Run failed 是此负向场景的预期结果 |
| 审批等待取消 | 最多 1 | 独立会话请求写入 cancelled.md，在审批出现但未领取前停止；文件不产生，许可撤销、执行与清理结束。该证据不冒充写入系统调用中途取消 |
| 原会话恢复 | 最多 2 | 重开宿主后恢复正常任务的原 Thread/Pi Session；依据原上下文回答合成事实；不得重做既有写入，原文件与 mtime 保持 |

阶段分配合计 8，但模型实际选择及轮数可能不同；这是上界而非成功承诺。实际需要更多请求或超范围操作时停止并报告，不自动追加授权。拒绝/取消的预期终态与验收程序失败分开记录；任一意外失败、清理未知或无法确认请求归属都停止本轮。

正常任务建议输入：读取合成资料，生成包含项目数量与合计的 summary.md，先标记 DRAFT，再用 edit 将该标记改为 FINAL，最后简要说明。只允许批准范围的文件；验收代码不得直接替模型执行 read/write/edit。

原会话恢复使用正常任务 Thread；拒绝和取消另建会话，避免负向历史污染正常任务。恢复请求需要原 Session 精确引用，不能选择“目录中最新文件”。M1 已有的真实流式取消证据保留，不把本轮审批等待取消扩大为所有取消时机均已验证。

## 4. 驱动的准入与停止

驱动准备阶段应输出只读计划：提交、配置摘要、授权范围、账本 used/reserved/remaining、输入文件摘要、目标不存在/版本、阶段列表和允许请求数。准备不读取密钥、不启动在线 Worker。新授权未批准则显示 blocked，不自动生成 approved=true 的配置。

执行必须使用独立显式动作，例如 execute-approved；调用前验证计划未变，并沿用同一个产品账本。保存 attempt、Thread、Run、逐请求身份、Operation、文件版本、原生引用和清理结果。重复启动不得重发已有尝试；中断只诊断或显式续验，原记录不可覆盖。

本轮已完成复审、修正、Mac 回归及本计划；**尚未实现新的 M2 真实验收驱动，也未运行任何真实请求**。该驱动是下一次有明确新授权范围后的小增量，可先用合成客户端/Provider 做离线测试。不要拿旧 validate:model-live 或 validate:model-resume 自动执行本方案。
