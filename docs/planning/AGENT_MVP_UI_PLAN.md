## 2. P0 主功能：一个真正可用的任务闭环

目标：选定批准工作目录 → 输入目标 → Pi决定文件操作或Bash → 显示命令/范围并批准 → 沙箱执行 → 输出回到Pi → 继续或结束 → 成果与历史保留。运行中可以停止，重启不重做旧命令。

示例验收目标：检查一个专用测试项目的目录，运行已有离线检查，把真实结果整理成report.md。命令由模型提出、结果由实际后端返回；不能预先写好报告或用固定演示替代真实模型证据。

| 增量 | 实现与复用 | 完成条件 |
|---|---|---|
| P0-A 动态Bash | Pi公开Bash定义/Operations接既有宿主/guardian；明确新工具授权 | 同Run多条顺序命令分别审批/领取/收据；不覆盖单一shell.json |
| P0-B 命令结果与取消 | 复用现有结果、超时、unknown/恢复 | 普通非零退出返回Pi供修正；拒绝/未知不自动重发；命令进程实际清理 |
| P0-C 工作目录与桌面入口 | 复用现有工作区/会话/工具卡 | 用户选定受控目录即可发送目标；展示cwd、网络策略、实际状态与停止 |
| P0-D 获授权的真实验收 | 使用现有驱动和产品入口，不另造模型循环 | 真实模型完成一个任务，留审批、命令结果、成果及恢复证据 |

Bash授权不能假称“仅Markdown”：它可能改动整个批准目录中的多类文件。首版保留现有Mac文件/禁网边界、独立环境、密钥不进入Shell和真实进程清理；不宣称恶意代码通用沙箱。旧配置缺省不开放Bash。

每条命令须有独立宿主身份和持久启动意图；先记录再派发，结果按命令核验。一次Run内多个操作的结果不能复制为统一ok。已知非零退出与未知副作用分开，清理成功不代表没有改文件。

PTY、插件市场、多账户、其他平台和生产发行均后置；真实调用仍需新预算，但其未获批准不阻塞离线产品实现。现有M1的4/4消耗不得清零；先前8次/$1仅为待批准提案。

## 3. 前端截图审查：保留什么，先修什么

[本轮实际截图与度量](../validation/ui-layout-2026-09-29.md)来自真实Electron、Pi Worker与合成Provider。截图覆盖待审批状态、三个窗口尺寸；不是生成的概念图。

| UI-P0 | 大标题、重复口号和输入区占用执行空间 | 已缩小页头/输入区、移除重复口号；保留权限说明，不删安全信息 |
| UI-P0 | 停止按钮偏小、关键说明字体过小 | 已增大停止/审批按钮和正文；未进行完整无障碍审计 |

## 4. 前端验收原则

至少验证1320×860、1024×720、820×640：无横向溢出，待审批按钮、输入框与停止位于可见区域；展开参数也不丢失动作入口。尺寸为CSS像素，PNG可为Retina像素。

审批范围、目标、数据去向不能仅靠颜色表达；命令允许滚动查看，不隐藏实际执行文本。消息/工具结果仍按安全纯文本展示。输入法、读屏、任意超长内容及真实模型设置页另作明确验收，不能由本轮截图推断通过。
