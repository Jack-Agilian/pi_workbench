## 1. 本文解决什么问题

目前已有可操作桌面、真实 Pi Session、实际文件与 Bash 执行、审批、持久化以及退出恢复。仍缺少的核心价值链是：**用户提交目标后，由真实模型决定回复和工具调用，工具结果再回到模型继续处理。**

本文收敛五件事：真实模型何时接入；Provider 用什么；沙箱哪些已采用、哪些待选；会话与执行如何命名；编码 Agent 下一轮应做什么、做到哪里停止。

本文不重新设计整个产品，也不要求完成通用沙箱、终端、全部连接器或所有 Provider 后才能验证真实模型。编制本文仅进行了资料核对，没有重新运行项目测试，也没有修改远端分支。

## 4. 术语与交互：会话不是一次执行

### 4.1 统一词汇

| 内部对象 | 面向用户的称呼 | 生命周期与含义 |
|---|---|---|
| Workspace | 工作区 | 确定执行环境中的目录与权限范围 |
| Thread | **会话** | 长期交流容器，包含多条消息和多次执行 |
| Pi Session | 原生会话 | Pi 管理的消息历史、上下文及分支；通常不向用户暴露技术名 |
| Message | 消息 | 一条用户、助手或工具内容 |
| Run | **一次执行** | 一次已接受请求及其自动模型／工具循环；允许无工具 |
| Turn | 模型轮次 | 运行时内部的一轮模型交互，不作为用户一级导航 |
| Operation / ToolCall | 工具操作／工具调用 | 有独立身份、授权、结果及审计的一次操作 |
| Task | 业务任务／目标 | 例如“完成季度复盘”；现在不新增 Task 表来容纳这个词 |
| Worker | 执行进程 | 可随 Run 回收；它退出不代表会话历史被删除 |

首版可维持“每次执行创建 Worker，结束后回收，下一次按原生引用恢复会话”。进程寿命、Run 寿命、Thread 寿命必须分开。同一 Thread 的后续消息默认继续原上下文；新 Thread 才是新会话。Fork 另走 Pi 原生机制。[R03][R05]

```text
会话：季度复盘                         ← 一个 Thread
├── “分析这两份资料”                   ← Run 1：读取、分析、回复
├── “把刚才的结论压缩成管理层摘要”     ← Run 2：继续相同上下文
└── “生成一份 Markdown 报告”          ← Run 3：批准后写文件
```

### 4.2 本轮文案修改范围

`apps/desktop/renderer.tsx` 中建议同步替换：

| 当前表达 | 建议表达 |
|---|---|
| 新建任务（实际创建 Thread） | 新建会话 |
| 我的任务（实际列出 Thread） | 最近会话／会话 |
| 发送任务 | 发送 |

| 大量任务卡包裹普通回复 | 普通消息时间线；工具、审批和失败状态按需展开 |

保持未确认命令的原意图与 requestId，不因改文案破坏 C02 的跨会话幂等修正。用户明确发送两次相同内容，仍是两次执行，不能按文本全局去重。

## 5. Provider：用 Pi 自带体系，不搭一套“pi-ai 网关”

### 5.1 默认调用路径

```text
桌面 UI：输入与模型选择
        ↓ 产品命令
App Server：账户/模型准入、Run、预算与权限
        ↓ 受监督的运行绑定
Pi Worker
  AgentSession：原生会话与工具循环
        ↓
  ModelRuntime：模型及认证接入
        ↓
  pi-ai Provider：请求、响应及流式协议
        ↓ 受控网络出口
一个已批准的模型服务 API
```

`pi-ai` 是模型访问库，不是本项目必须部署的独立网关。不要绕过 AgentSession，再在 App Server 写一个平行的 pi-ai／fetch／工具循环。ModelRuntime、CredentialStore 和单 Provider 单账户规则已存在于 SSOT。[R03][R04]

当前 `packages/pi-adapter/session-services.ts` 使用空 `InMemoryCredentialStore`、内存模型存储和无模型测试配置。需要增加**明确分离的真实模型组合入口**，保留现有离线测试入口。不能仅修改 `allowModelNetwork` 等字段就认定真实调用与隔离已正确接通；这些选项的准确作用仍以锁定发行包为准，OS 网络策略另行验证。[R04]

### 5.2 首版服务选择与待确认输入

首版只支持一个已验证的 Provider/模型组合，不进行自动故障切换、自动替换更贵模型或多账户路由。优先使用 Pi 已支持且用户确有授权的服务，不为第一次调用新增另一套 Provider 框架。

以下清单是**待批准的非秘密配置**，不是可直接运行的真实授权。API Key 不放在本文、Git、Issue、聊天记录或运行报告里。

```yaml
# 建议由宿主保存的授权元数据；字段为设计示例，不是 Pi 官方配置。
provider_id: null
model_id: null
approved_endpoint_id: null
credential_mode: memory_for_app_lifetime
allowed_test_data: synthetic_non_sensitive
max_provider_requests_including_retries: null
max_output_tokens_per_request: null
max_run_duration_seconds: null
budget_currency: null
budget_amount: null

```

没有这些必要授权时，可以完成代码、离线契约测试和模拟 Provider 测试；真实调用用例必须明确为未运行／被阻塞，不能自动使用用户全局凭据，也不能为了获得通过记录擅自消费订阅或本地模型服务。

### 5.3 凭据边界

宿主是账户配置的权威，Pi 通过公开 CredentialStore 使用当前批准的账户。首个内部验证可不落盘长期凭据；应用重启后要求重新配置，是可接受的已知限制。Keychain/DPAPI、OAuth、多账户可以后续扩展，不能把它们全部变成 M1 前置。

配置入口若由受控设置页接收用户手工输入，输入完成后应清除 UI 引用；常规会话 DTO、状态查询及日志不得返回原密钥。凭据传递使用单独受限、无日志、非持久事件的宿主接缝，不能塞入普通 `Run.input`、通用事件流或已持久化启动日志。不要承诺 JavaScript 运行时可以证明内存中所有秘密副本已被可靠擦除。

**Pi Worker 直接认证模型请求时可能使用明文凭据。**因此该 Worker 必须属于受信任执行代码，不加载未知可执行扩展；不把 CredentialStore 适配说成“Worker 无法读取密钥”。Shell/PTY 进程维持独立白名单环境，不继承模型凭据。[R03]

若未来要求“不可信 Worker 也不能取得上游长期密钥”，再采用已有的认证请求代理／网关来隔离；这是更强的信任模型，不在 M1 中暗自承诺。

### 5.4 模型网关与出口代理分别处理

| 对象 | 本轮决定 |
|---|---|
| Pi Provider 协议适配 | 直接复用 |
| 新建聚合、路由、统一计费网关 | 不做 |
| 用户已经部署的兼容网关 | 可作为后续受控端点；不是首版必需 |
| 限制域名、端口、网络访问的出口代理 | 可为真实模型的网络边界使用；优先成熟实现 |
| 在代理里重写工具调用／Provider 协议 | 不做，避免产生第二条模型协议栈 |

兼容端点也需要对所选模型的流式、工具调用、错误与用量行为实测，不能仅凭“OpenAI-compatible”等标签认定兼容。服务、endpoint 或模型变化应在下一 Run 明确生效，不静默改变当前执行。

## 6. 沙箱：保留已验证边界，按实际需要复用社区后端

### 6.1 已采用、候选与未完成

| 部分 | 当前依据或建议 | 状态 |
|---|---|---|
| Electron Renderer 隔离 | sandbox、contextIsolation、有限 preload、CSP、sender 校验 | 已有实现及限定验证，继续保留 |
| Mac Worker 隔离 | `sandbox-exec`、文件规则、禁网、Node 权限、独立目录 | 现有受限模式，不等于跨平台通用沙箱 |
| Mac Shell 隔离与清理 | 独立受管 Shell 组、独立环境、guardian、受保护收据 | D2-S 限定验证；须保留 S01 修正 |
| 模型联网配置 | 仅模型请求需要的受控出口 | M1 必须补齐，不直接解除全部禁网 |
| `@anthropic-ai/sandbox-runtime` | 原生文件/网络隔离封装候选 | **优先评估，尚未采用到本项目** |
| 完整容器／VM／远程后端 | 用于不可信扩展、高风险或无人值守工作 | 后置，未选定最终产品后端 |
| Windows | 独立平台和权限测试 | 未验证，不从 Mac 结果外推 |

现有项目依据见 `apps/agent-server/worker-launcher.ts`、`docs/ssot/d-platform-contract.md` 和相关验证报告。Node Permission、审批、进程组清理和 OS 沙箱分别解决不同问题，不能互相代替。[R01][R06]

### 6.2 M1 的网络要求

保持现有离线模式不变；真实模型使用独立、明确的联网配置。Provider 目标、端口和必要路径由宿主选择，不接受模型任意指定上游 URL 或认证账户。

模型请求能联网不意味着工具能联网。M1 不注册工具，M2 默认只允许文件工具；未来 Shell 接入真实模型时，Shell 的原禁网策略独立保留。出站限制不等于数据保密：发给已批准 Provider 的上下文本身仍是数据出境，须由用户确认数据范围。

优先用成熟的出口代理／沙箱库完成目标限制，验证实际 Pi transport 能通过所选路径工作。**仅设置 `HTTPS_PROXY`、仅在提示词限制域名、仅在 UI 隐藏 URL，都不能作为强制网络边界的证据。**未验证时保持真实调用阻塞，不为方便演示关闭整层保护。

最低验证包括：批准目标可达、未批准目标被拒绝、直接绕过代理被拒绝、重定向或端点变化不扩权、Shell 仍然禁网、密钥不进入日志和子进程环境、错误可脱敏展示。DNS/CDN、TLS、流式连接及本地端点需求以选定 Provider 的实际 transport 为准；不在本文虚构通用实现已可直接使用。

### 6.3 社区后端采用控制

`@anthropic-ai/sandbox-runtime` 官方资料描述了 macOS `sandbox-exec`、Linux `bubblewrap` 与代理式网络过滤，并标注研究预览。本文只把它列为可复用候选，不据此声称本项目已支持相应平台或具备生产级隔离。[U01]

只做一个与 M1 相关的采用验证：固定发行包与许可，确认能支持当前 Pi 模型出口和文件边界，验证与现有 guardian 的进程所有权不冲突。可满足则做薄适配；不能满足则记录具体缺口，选择已有可行实现或保持当前受限配置，不展开自研通用沙箱项目。

不得直接采用候选库的宽松默认读权限。产品数据库、收据、真实用户凭据和未批准目录的拒绝规则必须继续成立。第三方库的采用不替代本项目的审批审计、Run 结算和退出恢复。

## 7. 新路线与里程碑

M1/M2 是本建议使用的交付名称，不是新的 Runtime，也不替换已有 M0 Gate。实施前先检查是否与仓库现有 ID 冲突，再登记到 Backlog。

| 顺序 | 增量 | 用户能感知的结果 | 不作为前置的工作 |
|---|---|---|---|
| P0 | D2-S 修正收口、路线与术语同步 | 从正确集成基线启动，指令不互相冲突 | 重做已完成探针 |
| M1 | 一个 Provider 的真实无工具会话 | 能发送、流式回复、停止、重开继续上下文 | PTY、Windows、市场、完整 OAuth |
| M2 | 模型自主调用有限文件工具 | 能读资料、提出写入、审批后产出、继续修改 | 并行工具、多 Agent、任意 Shell |
| M2-S | 将既有 Shell 后端按需接到真实模型 | 模型可申请受管命令，正确处理结果与副作用 | 用户交互终端 |
| D2-T / D2-X | 单用户 PTY 及对应平台退出回归 | 用户终端、resize、Ctrl-C、受管清理 | 不再阻塞 M1/M2 |
| E / 其他平台 | 技能库、精选目录与平台扩展 | 更广的任务能力与可分发产品 | 不挤占首个真实 Agent 闭环 |

已开始的 D2-T 不必丢弃，可在独立分支保留；尚未开始则后置。Windows 有现成测试环境时可并行验证共享接口，但不是第一次 Mac 真实会话的合并条件。

## 8. M1：真实会话的最小实现和验收

### 8.1 实现范围

在现有 Worker 组合层增加真实模型驱动，通过 Pi 公开 `AgentSession.prompt()` 与订阅接入；不自己写 `while(toolCalls)`、Provider fetch、自动摘要或模型重试循环。保留 demo/test 驱动为可重复回归，但真实模式不能向原生历史写入合成 Assistant 来冒充模型回复。

无工具模式必须在实际 Session 配置上明确禁用全部工具与未知扩展，不能只在 system prompt 写“请勿调用工具”。实际消息仍经过产品 Run、绑定校验、受限展示和原生 Session 持久化。

当前 `ExecutionPlan`／结算逻辑为单操作演示设计。M1 只补零工具路径：**模型正常回答可以完成 Run，即使没有 Operation、文件或 Artifact。**不要为通过旧断言制造一个假的工具调用。[R07]

实时正文应来自所选 Pi 版本的真实文本事件，不仅在结束时调用 `SessionManager.getBranch()`。展示增量有界、最终消息可校验、控制事件优先；页面重连按已提交快照／原生记录恢复，不重新发起模型请求。M1 可以限制历史规模并明确提示，不强制先做无限历史分页。

取消调用 Pi 已验证的公开取消入口，并保留宿主超时清理；不能只停止 UI 打字效果。Provider 是否停止生成和是否已经计费不由本地 Abort 返回证明。普通认证错误、限流和网络错误不应自动转成“有未知文件副作用”；只有确实缺少相关执行／清理证据时才应用对应阻断策略。

### 8.2 M1 具名验收

以下是计划测试标识，不是已存在或已通过的命令。

| 标识 | 必须证明 |
|---|---|
| `m1-real-text` | 一条真实用户输入进入指定 Provider/模型，桌面显示真实回复，无合成替代 |
| `m1-zero-tools` | Session 的实际可执行工具集合为空，零 Operation 仍可正常 completed |
| `m1-stream-final` | 流式和最终回复不重复、不跨 Run；长回复有明确预算与截断行为 |
| `m1-context-resume` | 两次消息共享会话上下文，应用重开后按同一原生引用继续；不同 Thread 隔离 |
| `m1-cancel-close` | 生成中停止／关闭有真实结算；旧增量不得污染后续 Run；不承诺撤销已计费请求 |
| `m1-provider-failures` | 无效凭据、限流、断流、超时有固定错误和有限重试，不自动换账户／模型 |
| `m1-request-identity` | 确认丢失、会话切换和重连不自动重发；显式重试能对应原请求 |
| `m1-network-credential` | 模型出口与文件权限受控；配置秘密不进入 transcript、产品事件、日志或 Shell 环境 |

获授权的真实最小验收可采用三步：发送不含秘密的事实；在同一会话追问该事实；重开应用再追问。另做一次真实生成取消。测试内容、请求数、用量和取消结果单独登记。未授权时仅执行对应模拟用例，不把它们写成 `model` 证据。

## 9. M2：有限文件工具的基础 Agent

### 9.1 模型决定操作，宿主决定授权

```text
用户目标 → Pi 模型请求 → 模型提出工具调用
                          ↓
宿主校验归一化参数、目录、预算与当前 Run
                          ↓
读操作范围准入／写操作审批 → Pi 原工具 + Operations
                          ↓
工具结果返回 Pi → 模型继续判断 → 最终回答
```

从预先锁定整个 Run 的唯一输出，调整为**运行中逐 Operation 授权**。模型可以提出参数，但不能生成有效许可、改变运行环境或扩大自身工具集合。

需要修改的接缝如下：

| 现有演示约束 | M2 的最小演进 |
|---|---|
| Run 开始前预知唯一工具、路径和结果摘要 | Run 固定策略／模型／资源；每个调用到达后再固定其参数、目标与许可 |
| `one_operation_per_run` | 允许多个顺序 Operation；可以继续限制同一时刻只有一个活动操作 |
| 结束时用一个 `ok` 统一汇报全部工具 | 每个工具调用单独记录结果，Run 最后再综合结算 |
| 所有工具失败都导致整个 Run 不能成功 | 区分可反馈模型并纠正的工具错误、授权拒绝、未确认副作用、最终执行失败 |
| 无 Artifact 不能算完成 | 回答问题、仅做读取也能完成；Artifact 按真实产生情况登记 |
| 固定生成文件内容的 demo | 使用模型实际输出；不得用宿主预制答案模拟模型决策 |

实现落点优先是 `packages/pi-adapter/worker-runtime.ts`、`apps/agent-server/worker-supervisor.ts`、`apps/agent-server/core.ts` 及现有协议。不要新起第二套调度器。[R07]

### 9.2 最小工具与权限范围

首轮仅开放受管理测试工作区内的 `read`、`write`、`edit`。默认禁止 Shell、网络工具、未知扩展和任意路径；写入仍需宿主审批。每个工具保留 Pi 原 schema、参数准备、结果和错误语义；不复制编辑匹配、diff、文件搜索或输出裁剪算法。

对 write，可以在工具调用参数已确定后由宿主计算预期内容摘要；不要求在 Run 开始前知道输出。edit 的派生内容由 Pi 原算法生成，宿主保持目标、操作前版本与实际结果核验，不为审批另写一套编辑算法。审批卡须展示可理解的目标与改动内容／摘要，不能仅显示一串 hash。

复用现有同工作区写入准入、资源快照、原生引用、不可复用 runtimeBindingId、迟到事件与未知副作用规则。取消已经完成的写入不自动回滚；崩溃恢复不自动重发工具。

### 9.3 M2 验收场景

| 场景 | 通过标准 |
|---|---|
| 阅读两份批准资料并生成报告 | 由真实模型提出至少两个读取及后续写入，审批后真实文件存在，最终回复与成果对应 |
| 同一会话继续修改报告 | 复用原上下文和新 Run，模型实际提出 edit，保留版本与来源 |
| 拒绝写入 | 目标未写入；模型收到明确拒绝结果，不换工具绕过授权 |
| 越界读取／写入 | 被宿主和执行边界拒绝，不能通过模型生成新许可 |
| 工具出错后修正 | 原错误可回到模型；后续正确操作独立结算，不伪造早期成功 |
| 写入后、完成消息前中断 | 原操作对账，不重复写入；历史成果与当前文件状态分开 |
| 取消及预算到期 | 不派发新调用，已有副作用保留，清理与终态可信 |

M2 的“基础 Agent 可用”指上述限定 Mac 工作流，不代表任意插件、无人值守、全平台或生产安全保证。

## 10. 预算、错误与验证分层

### 10.1 预算不是只给输入框加一个限额

模型、重试、压缩、可能触发模型的辅助动作都应计入获批范围。模型请求次数、输出 token、运行时长和工具次数使用明确上限；达到上限先停止新调用，再按现有生命周期结算。

用量优先记录 Provider 实际返回值；费用估算需记录价格来源和日期，不保证与最终账单完全一致。模型取消、网络断开或客户端超时不等于 Provider 没收到请求，也不等于零费用。没有官方可用幂等能力时，不自行承诺模型请求 exactly-once。

工具执行、模型请求和产品创建命令采用不同的重试规则。沿用 Pi 原生有限重试并核验配置范围，不再外加一层无条件重试；未确认外部副作用始终禁止盲目重放。

### 10.2 不重置已有 M0 Gate，也不永远保持 pending

`docs/ssot/maintenance.md` 已定义 M0-UI、M0-SDK、M0-Pi 的证据类型。M1/M2 是交付步骤，不是另建一套验收标准。[R08]

| Gate | 本次处理建议 |
|---|---|
| M0-UI | 对照已有 Mac 桌面、审批、取消、恢复证据逐项核对；确有缺项写明，不因文档数量多或未做 Windows 就机械 pending |
| M0-SDK | 核对锁定发行包、原生 Session、资源和宿主接缝；不把真实模型作为其隐含要求 |
| M0-Pi | M1/M2 获授权真实模型与 Mac 产品闭环证据齐全后评审；M1 仅聊天通过不自动完成全部 Agent 范围 |

不能静默降低 Gate。若某个大 Backlog 项同时包含当前与后续能力，应显式拆分范围、保留来源与依赖，而不是伪造 done 或让一个未来平台子项永久阻塞不相关的当前交付。

### 10.3 测试入口

保留现有 `npm run typecheck`、A/B/C/D 回归及 SSOT 检查。建议新增名称如 `test:model-integration-offline`、`test:model-live`、`test:agent-live`，**这些名称目前只是提案，不是已存在的可运行命令**。

默认回归不调用真实模型。真实调用命令必须显式选择、检查授权范围与非秘密配置；凭据缺失即停止真实测试。模拟限流、故障、超时和越界可大量离线覆盖，真正 Provider 验收保留最小必要调用。Mac 全链路与 Linux 纯逻辑测试分别记载。
