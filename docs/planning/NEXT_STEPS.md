### 1. M2-A：同一 Pi Session 的有限文件 Agent

这是 MODEL-03 的实现增量，首先写清最小契约再集中实现，不建立另一套Agent Loop或新Task表：

| 接缝 | 必做变化 | 保留的所有权 |
|---|---|---|
| 模型循环与传输 | 允许一个Run内多次顺序LLM请求；每次有宿主绑定身份/独立额度预留与传输生命周期。迁移当前model_requests的run_id唯一限制，保留旧行；不能简单删除一次请求门禁 | Pi决定继续/工具/结束；宿主拥有预算、传输和绑定，自动重试默认关闭 |
| 文件工具 | 复用公开read/write/edit及Operations；仅批准workspace及资源；核对当前发行版支持的顺序执行扩展点，收敛同一Run零到多个顺序操作 | Pi保有工具实现，Worker不写产品库；M0全局单写和同provider单账户不变 |
| 审批与结果 | 每个Operation分别绑定参数摘要、目标、fileVersion、资源lock、身份和期限；允许/拒绝后独立记录领取和结果 | 宿主产生权限，不能把Run末尾的一个ok复制给所有Operation |
| 结算与恢复 | 首个操作成功、后续失败时保留各自事实；文件已写但确认丢失只核验不重做；旧绑定和迟到结果仍属于原操作 | 原生Session归Pi；最终Run结果结合模型、操作及实际进程清理 |
| 桌面 | 复用已有输入、流、审批、工具摘要和成果卡，支持多个操作；审批中的等待和错误原因可见 | Renderer仅产品DTO，不透传整个SDK对象或凭据 |

本增量不开放模型自由Bash、PTY、未知扩展、更多Provider、OAuth或市场；既有Shell实现保留回归。网络出口、资源加载和基础工具继续复用既有边界。预算按实际LLM请求计，不按Run计；工具结果触发下一次模型请求同样消耗额度，发送前预算不足须停止。

### 2. M2-B：集中离线验收

先用合成Provider驱动真实SDK、实际受限Worker/IPC、临时workspace和真实SQLite。覆盖零工具、单工具、多顺序工具、逐次允许/拒绝、版本/资源变化、等待审批取消、执行中取消、前成功后失败、写入后结果丢失、宿主/Worker退出与重开。重复命令只确认原结果；事件重放不执行工具或再次访问模型。流式空闲与总期限、完成/超时竞态、请求预算跨重开与修订保留一并验证。

实现稳定并先提交代码，再集中执行类型、A1–A4、ProductCore/SDK/Worker、模型、桌面、Shell/退出及SSOT检查。失败定位后仅补跑受影响范围；新增代码改变公共接缝时再扩大范围。报告逐项标明真实文件/进程与合成模型，代码SHA先存在，证据随后提交。

### 3. M2-C：独立的真实验收计划

离线通过后再准备可审核的真实场景及调用数上界、费用预留、输出上限、合成数据和允许文件范围。新请求需新的明确授权，不能复用已耗尽的4/4、清账或自动换授权ID。一个多工具场景可能含多次模型请求，预算计划必须计入这些继续调用；拒绝/取消/恢复场景分别计划，不以实际服务作为调试循环。

只用原有已配置Provider/模型，真实场景须证明模型自行选择工具、宿主逐操作授权、原生工具产生文件/结果、模型利用结果继续，以及取消/恢复边界；不硬编码模型将调用哪个工具来冒充Agent行为。任何场景失败立即停止，回到离线定位，不自动补发。

## 2. 暂定目录：减少不必要拆分

```text
apps/desktop/            # Electron/React
apps/agent-server/       # 一个模块化宿主，含产品/资源/审批/成果模块
packages/app-contracts/  # 可校验跨进程DTO
packages/pi-adapter/     # Pi公开SDK与Operations薄适配

```

Mock/fixtures 先作为测试与开发入口。每个目录不必都成为独立发布包，不增加自研插件微内核、通用RPC生成器、Provider层或npm解析器。

## 3. 社区复用准入

`pi-gui` 优先考察 thin SDK driver、timeline/diff/terminal；`OpenPi` 优先考察 Customizations/资源配置与特权边界。只在固定提交、许可证和模块依赖核查后局部移植；不同时拼六套应用。Pi TUI组件不作为React组件使用。

Pi server/client/Chord/durable 按 [SSOT](../ssot/reuse-first.md) 记为评估项；发布、认证、持久化、平台和接缝能力证明前不替换SDK主路径，也不自研同功能框架。
