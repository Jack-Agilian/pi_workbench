# 共享尺寸与视觉参数

ID：FOUNDATIONS。归属：[规格树](README.md)，不是独立页面。以下全部以CSS px计；窗口外框/系统标题栏不计入内容区尺寸，200%以实际CSS视口决定断点，不用物理屏幕分辨率推断。

## 空间预算（目标v1）

| 参数 | 目标与选择理由 | 当前源码事实 |
|---|---|---|
| 导航宽 | 默认224，最小180，最大360；保持正文优先，用户可拖宽长名称 | pane-layout已有该组宽度；窄窗默认280 |
| 成果宽 | 默认328，最小280，最大640；够容纳文件摘要，长内容由预览换行/局部滚动承担 | 已有；空间不足时动态上限优先 |
| 主会话保底 | 并排时至少360，宽度变化不能挤掉输入/停止；空间不足改覆盖，不缩字号 | 已有主要约束；需按目标控件复验 |
| 正文与输入共同轴线 | 内容最大840；标准左右留白24，窄窗12；正文/输入左沿相互对齐 | 正文上限840；输入目前未统一同一上限 |
| 顶部 | 常态最小56，标题/目录可扩到72；动作确需换行时自然增高，不能裁掉停止 | 目前由padding/文字决定，需收敛 |
| 输入 | 文本区最小56、上限150且不超过可用会话高度的30%；工具栏32，外内边距12，底部安全留白12 | 现有56/150及部分低高度覆盖，目标还需共同预算 |
| 控件 | 常用高32，主动作36，紧凑图标命中框至少28×28；图形16，重于尺寸的是清楚焦点/名称 | 现有控件多套padding和尺寸 |
| 字级 | 正文14/行高1.7，操作13/1.5，辅助12/1.5，标题16/1.4；不靠9–10px压密度 | 现有辅助多处9–11px；目标待实现 |
| 间距/圆角 | 间距4/8/12/16/24/32；控件圆角6、浮层8、输入12。按角色选值，不逐组件造数 | 现有值分散 |

参数是项目设计选择，不是社区标准或无障碍认证。节点表中的标准32控件、28命中框、字级等是对本表的应用，不是独立可改值；本表变更时Skill须核对所有引用节点并同步，局部不同值需写理由（如权限带说明的多行选项最小44）。颜色沿用现有语义角色（正文/辅助/边界/选中/警告/危险），重构时统一token并核对各状态对比度；不在每页重复色值。字体沿用系统字体栈，不因设计升级加载远程字体。

## 响应布局与溢出

视口宽≥1000：可并排导航、主会话、成果；700≤宽<1000：成果覆盖主会话区域；宽<700：导航也作为覆盖层。断点归本文件所有，代码边界必须一致（现有JS `<700` 与CSS `max-width:700px` 在700处需成组核对）。导航/成果同时打开时只允许一个模态覆盖层取得焦点；背景区域按[层级规则](motion.md)处理。

并排预算先给主会话360，再在导航/成果各自上下限内分配；不能让两个分隔条各自认为拥有全部剩余空间。1320宽、默认导航224和成果328时主会话768，扣两侧24后阅读宽720；成果关闭时正文封顶840；820宽时成果覆盖而非继续挤压。这是算术设计校核，不是实测截图。

宽窗子区域最小宽设为0以允许收缩；路径/名称默认省略但提供可达完整内容；代码/表格局部横向滚动，不给整个窗口制造横向滚动。高度不足时压缩装饰留白、收起次要说明，必要时反馈区/正文局部滚动；不能以无限增长的通知或输入区挤没正文和关键操作。窗口外框最小820×640沿用main.ts；实际CSS高度<500（含缩放）须额外检查。
