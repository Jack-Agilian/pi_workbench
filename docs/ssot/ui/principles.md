# 工作台信息层级与交互设计准则

2026-10-08迁入空间规格树。源于用户对“权限：当前模式”和页面信息平铺的纠正。本文件约束后续设计，**不是已实现清单**。既有职责、当前代码与验证范围仍见[UI契约](../ui-experience-contract.md)；执行方法见[项目Skill](../../../.agents/skills/workbench-ui-design/SKILL.md)。

## 用户任务与页面结构

用户先找回工作，再提出目标、观察执行、作出必要决定、检查成果。默认布局延续左侧导航＋主会话；右侧围绕当前文档按需展开，可调宽和收起。布局服务当前任务，不把数据库字段、实现模块和所有可用功能逐项摆成页面栏目。

会话正文是阅读主角，输入是创建下一任务的主要动作；工具提供执行摘要，成果提供可核验对象。每个区域的主要动作清楚，次要动作降低视觉权重。全局状态只在其影响全局时出现，单次操作的问题就近呈现；不让一条错误在顶栏、消息和侧栏同时重复大段解释。

## 四层信息展示

| 层级 | 适用内容 | 设计要求 |
|---|---|---|
| 常驻 | 当前对象/模式、主要动作、影响当前判断的状态 | 以值、对象和动词表达，语境清楚时省略“权限：”“状态：”等重复字段名；保留必要表单标签及辅助技术名称 |
| 悬停或聚焦提示 | 简短动作解释、快捷键、辅助辨识 | 补充已有控件，不代替可发现的入口、关键风险或错误；鼠标与键盘均能获取 |
| 点击展开 | 选择项、完整路径、版本来源、工具详细输出、诊断 | 与触发对象相邻或进入明确面板；可关闭、可返回；包含可操作内容时不能伪装成提示气泡 |
| 情境出现 | 待审批、保存中、确认丢失、失败、清理中、版本不匹配 | 在影响用户决定时主动可见，并提供准确后续动作；信息过期后退出，不用装饰性成功状态覆盖未知结果 |

精简需要降低认知负担。把一切藏入悬停、全部改成图标、把字号缩小或把所有内容包成卡片，都不能达到这个目标。普通表单仍需要标签，密钥配置和安全决定不能只靠占位文字或气泡。

具体区域的职责、位置、尺寸、子控件和状态只维护在[空间规格树](../ui/README.md)。权限的值入口、提示和保存反馈由PERMISSION节点持有；各区域不再在本文件复制一张平行规格表。

## 视觉与交互一致性

- 用文字层级、间距和对齐建立主次，边框/背景只分隔确实独立的区域。避免卡片套卡片、重复标题、到处使用主按钮和无意义留白。
- 一组改版先列出已有与拟调整的正文/辅助文字、控件高度、间距、图标尺寸、圆角、颜色和弹层层级；由共享样式承接，不逐组件任意造值。以实际窗口核对可读性，不能从Retina截图像素直接推断字号。
- 同类动作使用同一名称、图标和交互方式。图标适合熟悉的次要操作；难以辨识或后果重大的动作保留文本。装饰图标不重复朗读控件名称。
- 提示气泡只解释，不承载按钮、关键错误或审批。自定义提示可通过Escape关闭，指针可移入提示阅读，聚焦时可见，不抢焦点；内容无需悬停也能通过正常动作理解。长内容用展开区域。
- 弹层不挤乱主布局，检查边缘避让、滚动容器裁切和缩放；不因每次轮询自动打开或抢焦点。关闭后返回合理触发点，嵌套层只关闭最上层；非模态弹层不盲目困住Tab，模态覆盖需明确焦点边界。
- 窄窗优先调整结构/折叠次要区域；审批目标、输入和停止仍可达。流式内容、展开详情和拖动栏宽不得打断用户阅读旧记录或丢草稿。

## 两条独立验收线

成组改版先写短设计说明，并将受影响区域分为操作与阅读：导航、输入和审批保证动作明确；正文、代码和成果预览保证连续阅读及稳定滚动。二者共享设计规则，不共享同一种信息密度。先做关键控件的默认/聚焦/展开/忙碌或错误状态样例，以真实长度的中文、路径和窄窗检查，再推广到整条路径。删除冗余结构优先于视觉微调；共享数值与动效维护在空间树的FOUNDATIONS/MOTION节点，具体控件维护在对应叶节点；现有样式承接实现，不增设竞争的设计权威文件。

**设计线**检查信息是否必要、层级是否清楚、入口是否自然、反馈是否适时：对受影响区域给出默认/展开/异常及宽窄窗口的画面或明确示意；逐项回答用户能否辨认对象、发现动作、理解结果。发现平铺问题后应成组修正，不能以旧功能测试通过宣称视觉已成熟。

**行为线**验证协议/权限/身份、保存与恢复、键盘和焦点、缩放、草稿与阅读位置。只读刷新不变成重启宿主，恢复不重发副作用；正文和Operation继续按可信身份展示；当前缺少跨列表关联时保留独立区，不能为排版猜测时序，也不能把降级永久当成产品阅读目标。

代码审查、合成自动化、实际桌面代理操作、用户验收和VoiceOver听读分别记证据。现有平台工具故障不能阻止设计方案和独立实现推进，也不能被改称产品已通过。每批集中验证受影响链路；真实模型另按已有授权做整批验收。

## 参考落实的检查

参考必须具体到本次区域及状态。记录实际看过的默认/展开/异常画面或源码行为，比较信息密度、动作位置、提示时机及焦点路径，说明本项目采用和偏离的原因。只有文档介绍时如实注明，不能推断竞品细节；只采用三栏结构、配色或某个片段不等于复用了成熟交互。后续画面对照用于证明设计决策已落实，功能测试和Skill格式通过都不能替代这一检查。
