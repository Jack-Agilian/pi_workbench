# COMPOSER 输入区

ID：COMPOSER。父：[CHAT](../README.md)。子：[PERMISSION](permissions.md)。职责是用户对任务发出输入与决定的稳定位置，不是配置总面板。当前审批借用TOOLS拥有的子控件，固定在输入框上方；历史只读记录不复制决策按钮。

| 子节点 | 位置/尺寸 | 要求 |
|---|---|---|
| COMPOSER.DRAFT | 上层全宽，最小54/上限160与FOUNDATIONS高度预算取较小值 | 自动/手动增高仍有上限，之后文本区内部滚动；不随流式输出收缩/丢字 |
| COMPOSER.BAR | 下层32高，间距8 | 左侧PERMISSION，右侧发送；单次批准/拒绝属于上方审批区域，不混进权限模式选择器；模型名作为紧凑信息入口；删除常驻“Pi·文件与Bash”能力清单，不增加没有协议的模型切换 |
| COMPOSER.SEND | 最右32高 | 发送/加入队列/重试未确认请求准确区分；没有有效输入不能提交，原因就近可得 |
| COMPOSER.HINT | 区外底部12号短提示，非必要可按需 | 快捷键归发送hover/focus；运行时就近说明新输入是下一Run排队。关键失败/未确认放区内可见，不借气泡隐藏 |
| COMPOSER.DEMO | 仅无模型演示空态的次要展开项 | 明确合成；只填草稿，不变成正式产品execute-anything入口 |

外框内边距12、圆角13，宽度跟正文共同轴线；边框/聚焦强调只围输入整体。窄窗权限与发送必要时换行而非压小文字；高度低时先收起说明，再限制文本区，保留阅读区可用。没有会话时给出新建原因；未确认请求保留原文与原身份，不自动发新的。

键盘沿用既有IME保护及Enter发送/Shift+Enter换行；不在重构中另写提交判定。草稿按Thread身份保存；权限保存未确认时不让新Run以错误模式发送。

源码：renderer composer、[composer-key](../../../../../../../apps/desktop/composer-key.ts)。现状已有草稿/排队/确认重试，输入横轴和工具栏技术标签需收敛。验收：中文输入法、长草稿、空输入、活动排队、确认丢失、切会话、低高度/200%，发送不重复。
