# 空间规格树维护

输入：本次用户目标、受影响组件/样式与当前规格。输出：同批更新的唯一规格节点、代码/规格差异说明、实际验证证据；只做设计时明确待实现。入口：[UI规格树](../../../../docs/ssot/ui/README.md)。

## 查阅与更新顺序

1. 先读树根、principles、foundations、motion，再沿父链读目标节点；查父节点的子空间表及共享本控件的其他区域。不必把全部历史报告每次重读。
2. 确认本次改变的是职责、位置/尺寸、信息层级、控件状态、动效/焦点还是产品行为。几类可同时改变；业务语义仍回其契约，不搬进视觉文档另立权限。
3. 在动手前写目标变化和现状差距。由父节点决定空间分配，叶节点决定内部交互；共用数值/动效只改FOUNDATIONS/MOTION。特别核对宽度改变对兄弟、低高度/缩放、阅读锚点和弹层避让的影响。
4. 新区域先在父子表和树根索引登记，再写节点；简单按钮留在父页的子节点表，有独立复杂状态才拆文件。稳定ID不随组件改名变化；移动节点同步父链/链接/源码映射，删除说明替代入口。不要为了树形外观给每个图标建空文件。
5. 有授权则按一组完整行为实施。数值或动作中途调整时同批更新规格，不能以“源码已经这样写”默默覆盖约定；保留理由与未验证状态。没有改变设计语义的bug修复可报告“节点已核对，无规格变化”，不要求制造无意义文档diff。
6. 交付前核对节点职责、子控件覆盖、链接、旧规则是否仍有重复权威、当前实现/待实现/已验证是否区分。检查受影响父子与兄弟状态，报告节点ID及实际测试。更改NEXT_STEPS/backlog时保持唯一当前事项，不用规格完成宣称功能完成。

## 节点最小模板

```markdown
# ID 区域名称

ID：稳定标识。父：填写父区域的相对链接。子：填写独立子区域的相对链接。
职责及非职责；状态：目标待实现 / 部分实现 / 已实现（附范围与证据）。

| 子节点 | 位置/尺寸（引用共享参数） | 功能、默认/展开、主要动作 |
|---|---|---|
| ID.CHILD | … | … |

状态：空/加载/成功/失败/未确认等本节点相关状态。
响应与溢出：宽窄/低高度/长内容；滚动归属。
交互：鼠标/键盘/焦点/开合，引用共享动效并写必要例外。
代码归属与业务契约；当前源码事实/差距、观察基线。
验收：本节点可观察条件、相关父子影响；证据链接及未测项。
```

可以合并自然相邻段落，不为模板造占位章节。禁止把未测动画时间、方案截图或文档链接检查记成实际体验通过。

## 变更影响示例

| 变化 | 必查/更新节点 | 关键检查 |
|---|---|---|
| 导航收起动画 | MOTION、SHELL、NAV、WORK/CHAT | 宽度预算、反向点击、焦点、断点、阅读位置与减少动态效果 |
| 权限入口面板 | PERMISSION、COMPOSER、必要时MOTION | 弹层边缘、保存未确认、旧Run固定权限、发送空间 |
| 成果预览增高 | PREVIEW、ARTIFACTS、WORK | 列表与正文滚动隔离、关闭焦点、低高度；不改文件权限 |

文档批次用现有Skill格式/元数据、本地链接、SSOT与脚本检查；实现批次按当前package.json做受影响验证，动效需实际连续观察。现场工具故障如实记录，不重跑旧测试掩盖。维护选择：DOC_UPDATE用于规则/节点/入口变化，确有稳定重复机械步骤再考虑SCRIPT_UPDATE；当前不另建树编辑器或重复索引数据库。
