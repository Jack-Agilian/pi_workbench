# 筛选后的桌面设计工作流

这是项目自有方法。上游来源、固定提交、许可和拒绝范围见[社区研究](../../../../docs/validation/ui-design-skills-research-2026-10-08.md)；详细呈现规则只维护于[UI规格树](../../../../docs/ssot/ui/README.md)的对应父子节点，不再建立另一份DESIGN.md或第三方设计数据库。

## 一次成组改版

1. **短设计说明。** 写清使用者正在做什么、当前障碍、成功时看见什么，以及本轮影响区域、必要状态、内容长度与窗口范围。已有明确上下文时直接形成说明，不重复询问已授权事项。
2. **按区域分配注意力。** 导航、输入、审批是操作区域；正文、代码、成果预览是阅读区域。操作区域强调可发现的动作和准确反馈，阅读区域强调连续阅读、代码可读和稳定滚动。整体共享控件、语义颜色和间距；不能把工作台套成营销首页。
3. **先删减结构。** 对当前区域每项信息选择保留、合并、按需展开或删除重复项，并说明理由。保留功能的可达入口与必要事实；若布局或信息组织有问题，先解决它，再调圆角和动画。不能只缩字号、换配色。
4. **制作关键状态样例。** 选一组能代表本轮问题的控件，例如权限入口＋选择面板＋保存未确认；并列展示默认、聚焦、展开、忙碌/错误。检查真实长度中文、同名文件、长路径和窄窗。已授权实现时可直接在现有组件上制作；不新装组件库或绘图系统。静态示意必须标合成，不能充当真实键盘证据。
5. **用样例校准共享规则。** 明确沿用或修改哪些文字、间距、控件高度、图标和表面层级。优先现有组件与原生语义；确有缺口才核对可访问组件的公开API。按[空间维护流程](space-spec-maintenance.md)把决定写回对应节点与共享样式，不逐组件漂移，不为一次例外创建大设计框架。
6. **推广到整条任务路径。** 按信息主次统一导航、消息、工具、输入及成果中本轮涉及的部分；错误就近，恢复有下一步，执行状态由宿主事实驱动。工具只显示产品已批准的摘要，不从原始SDK对象生成“丰富详情”。
7. **分别复审设计和行为。** 设计审查看实际渲染后的主次、密度、可发现性与阅读节奏；行为检查语义、键盘、焦点、草稿/滚动和身份边界。记录“观察到的问题 → 用户影响 → 本批修正 → 验证方式”，按影响解决；不以检测器零报错、截图漂亮或测试数量证明另一条线通过。

## 检查顺序与停止条件

先处理阻断任务、错误状态及不可达动作，再补必要状态、统一信息层级与组件，最后处理视觉细节。一批集中回归；出现新失败或新改动才补验证，不把每个CSS改动变成一次真实模型测试。完成本次受影响路径的检查并明确剩余未测项即可交付，不新增通用审批门槛或无限打分循环。

本项目不照搬移动端固定尺寸、营销式独特视觉要求、任意工具撤销、估计剩余执行时间、通用暂停/恢复、强制自动代理审查或第三方脚本。相关能力只有在产品协议已有事实与授权时才能展示。
